## 目标与用户价值

用户在消耗计算资源之前，能检查 epwflow 的输入与环境，知道哪些参数、程序或已有结果不符合要求；执行时能追踪状态，并让后续所有阶段共用资源限制、防重复提交和恢复机制。

本 Feature 独立交付预检和执行基础。实际 QE/EPW 科学阶段由 F2–F4 接入，不能把本 Feature 通过说成完整超导流程已可用。

## 本次范围

1. **独立 Rust 入口与配置检查**：新增 epwflow 家族入口；检查结构、赝势、工作目录、声子模式、超导模式、物理参数、温度搜索限制、外部程序与资源配置。未知字段、无效枚举、非有限数值、非法范围和超预算请求明确报错；支持范围以已确认 Epic 为准。
2. **环境与版本证据**：区分配置可解析、文件可访问、程序可启动、版本已验证。优先适配指定 QE 7.4.1 配套 EPW；源码声明或目录名不能代替运行证据。需要计算资源的探测走受控任务并计入预算，普通检查不暗中提交任务或运行科学计算。
3. **路径与输入绑定**：相对路径按配置文件所在目录解析，默认 outdir 为 ./tmp。运行目录独立；记录输入、赝势、程序与阶段依赖的指纹，不覆盖历史结果，不修改被复用的源数据。预检结果不保证实际执行前输入仍未变化，执行和复用时必须再核对。
4. **状态与恢复基础**：记录阶段、作业、尝试次数、失败原因、依赖和预算。查询失败/状态未知不能视为任务已结束；已提交、计算结束和数值成功分别表示。多个入口同时操作或进程在提交边界退出时，能够避免重复计算并保留诊断信息。
5. **原生 Slurm 与预算约束**：严格处理提交退出码和作业号；成功依赖、失败阻断、有界重试。提交前预留节点时间，实际使用后结算；未核实的作业继续占用预留额度。所有真实试算、手动参考、失败和重试共享同一验收预算，不能通过切换模式或新建运行目录重置。
6. **统一资源限额**：本次验收每作业最多 1 节点、64 MPI、2 小时，同时运行最多 2 个作业，累计 8 节点小时、运行数据 100 GiB。检查存储预算及可用空间；达到限制停止追加，保留现场。参数可表达更小请求，不能悄悄扩大本次授权上限。
7. **公开说明**：帮助和手册直接列出检查、准备、资源内运行、提交、状态与续算的入口及副作用；未接入的科学阶段明确说明不可执行，不返回伪成功。具体命令拼写、配置字段和状态结构在本 Feature Spec 中统一定义。

## 用户场景与可验收结果

| 场景 | 预期结果 |
| --- | --- |
| 从另一个目录检查同一配置 | 解析到相同输入；不启动作业；缺项报告字段或路径 |
| 请求不支持的模型、非法温度或资源 | 在科学程序运行前拒绝，并给出原因 |
| 配置写着 EPW 5.9，但可执行程序未知或不同 | 报告未验证/不兼容，不当作版本通过 |
| 两个提交入口同时操作同一运行 | 同一阶段只产生一个有效提交；其他入口能识别已有任务 |
| 调度失败、响应丢失或进程意外退出 | 保留提交尝试；先核对调度记录，不能盲目重提或放行下游 |
| 查询服务不可用 | 明确状态未知，不释放未核实预算或重提任务 |
| 改变输入或复用数据被修改 | 不误用旧完成标记，指出失效依赖 |
| 预算不足或空间不足 | 拒绝新增任务，不删原始数据，不返回计算成功 |
| 中途退出后重新启动 | 状态和累计预算保留，已成功且仍有效的阶段不重复执行 |

## 验收标准与证据

- 配置和路径测试覆盖三种 PH 模式、两种超导模式、默认 tmp、显式 outdir、跨目录启动和上述非法输入；所有被声明支持的组合按同一契约解析。
- 使用独立进程的模拟调度器验证依赖、作业号解析、并发提交、提交边界崩溃、查询未知、部分提交失败及恢复；不能只 Mock 掉关键提交边界后声称通过。
- 预算测试覆盖恰好达到上限、超限拒绝、并发预留、失败结算、未核实作业、不同运行共享账本，以及进程重启后不会归零；零节点时间消耗的排队与已消耗运行时间正确区分。
- 有效任务必须经过阶段自己的产物与数值校验才可完成。F1 用有明确产物契约的测试阶段证明执行基础；真实科学验证归属 F2–F5。
- 帮助、预检结果和状态输出能区分“配置通过”“运行版本已验证”“阶段完成”“工作流完成”，不得混淆。
- 回归已有 qeflow 等入口，确认公开语义不变。测试证据写入后续 acceptance.md；需求检查通过不等于运行验收通过。
