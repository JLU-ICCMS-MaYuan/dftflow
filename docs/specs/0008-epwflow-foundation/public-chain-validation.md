# 三个公开入口的连续执行验证设计

本批落实三程序 FR-014～017、SC-008～011 的执行契约与 FR-006／SC-006 的恢复子集，沿用 T041／T042。真实 PBE／Tc 的科学验收不由进程替身替代。

## 当前缺口与职责

实施前，三个程序测试覆盖帮助、生成、预算、依赖提交和失败入口，原生模块分别覆盖 QE、比较与超导；本批补齐三个公开程序顺序执行同一固定请求的成功交付与最终绘图失败恢复。使用原生产执行、严格清单与校验器，不在测试中预造阶段成功清单。

工作流只编排阶段和记录完成证据；原生执行、分类、结果包发布与绘图仍分别由现有模块拥有。只读检查不修复数据。显式恢复必须保留已经验证的 SCF／PH、粗细网格及求解尝试；结果包清单的存在不能代表图表交付已完成，也不能阻止所属交付模块接续未完成发布。

## 验证设计

在指定 local_run 下保留新编号证据；Python 仅作为隔离原生进程与调度查询替身，生产仍为 Rust／Bash。共享当前 QE／EPW 文件协议替身和超导进程替身；修改测试目录层级后，重读从唯一祖先科学目录，或同一测试根目录的原 run 读取 NSCF；规范化路径去重，不使用固定历史绝对路径。

一次完整测试通过三个公开程序分别执行第一、二、三阶段，验证：

1. 第一阶段来自共享 qeflow，具备 SCF 冻结副本、均匀 NSCF 和 EPW save。
2. 第二阶段自动参考、纯能量选窗、独立质量、四类图与总览；细网格和超导尚未执行。
3. 第三阶段细网格、两模式搜索和双初值通过生产原生接口消费进程替身输出；以不同预设分类边界验证两模式不混用。样本数值显式标记为合成接口数据。
4. 在最终图目录放置测试自有的冲突文件，确认科学阶段完成但整个流程失败；移除该测试冲突后显式恢复，原生调用数和已有阶段哈希均不增加，完成结果包和全部三格式图。模拟最终交付根目录遗留的四类锁，显式恢复只能在锁归属原分配且该分配终态明确时回收；复用现有锁校验，不删除未知现场。
5. 完成状态、预算结算、复制到新位置后的只读核验／重绘与篡改拒绝均通过；不调用真实 Slurm／科学程序、不切换安装、不使用或修改原预算账本。

## 部分格式的文件归属

原生超导图与比较图保持同一归属原则：同源重绘 SVG 时保留已登记、哈希有效的 PNG／PDF；原生图源摘要改变时须全格式重绘或新目录，比较图源改变仍须新目录。通过独立文件级用例复现旧版丢失归属及后续未知冲突，再验证来源变更与篡改拒绝。该修复复用 F5 发布器，不改变科学数据所有权或尝试计数。

## T047：原生超导部分清单续算

沿用 FR-006／SC-006 与 F4 的既有显式恢复契约。静态检查发现，工作流通用补登记分支将所有已存在清单视为成功候选；F4 的合法 partial 清单因此在进入 Engine 前被完整成功门拒绝。先通过同一公开连续测试复现：测试自有标志令 iso 首次进程退出 17，aniso 正常完成；移除标志并显式恢复，要求成功模式与失败证据保持、失败次数保留、新尝试追加，粗细网格不重算。随后继续覆盖最终交付冲突及仅恢复 F5。

数据仍由 F4 持有。工作流只有在清单版本、run_id、当前 F3、所选模式、固定配置、搜索状态和全部已发布产物通过重验后，才能将合法 partial 交回 F4 恢复；完整清单仍可补登记，损坏或来源冲突必须拒绝。此处不增加自动重试策略，不运行真实数值诊断，不修改科学阈值或原预算。
