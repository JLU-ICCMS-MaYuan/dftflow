## 2026-10-20：仅变更 MPI 的粗阶段恢复

沿用 FR-006／SC-006 与 0012 FR-010，问题属于恢复实现缺失，不要求重新计算已核验的 QE 数据。原始配置和运行绑定保持不可变；新增尝试级 `mpi_override`，仅允许在尚未交付 Wannier 的失败第二阶段显式调整单 image 的 MPI／pool 数，并同步启动器、EPW 参数、Slurm 请求和预算请求。后续阶段继承同一设置，不支持在粗阶段完成后改变矩阵元并行布局。

科学请求身份仍按已验证的原固定配置计算；只有当前配置与该固定配置恰好相差上述执行并行度时，才允许使用原请求身份，保留既有独立参考和粗阶段失败归档协议。结构、赝势、程序、网格、能窗或质量门变化不属于此例外。执行资源由工作流尝试记录持有，F2／F3 继续分别拥有数据清单、原生尝试和质量校验，不更改数据所有权，不手改快照或历史清单。

验证映射：FR-006／SC-006 → 尝试级执行参数与原固定请求 → foundation 工作流、F3 请求校验 → T051 → 独立进程中失败粗阶段显式恢复、QE／参考调用次数不增加、原数据哈希不变，以及活动作业／不兼容配置拒绝。真实科学结果需另外验收，本次不自动提交作业。

## T049：实时分配与终态计费的事实来源

PBE 作业 1295894 已通过环境和动态加载，随后在科学程序前因 sacct 节点数为零被启动门拒绝，作业控制器分配记录为一节点。旧启动门依赖记账快照，不能假设与调度控制器同步；不猜测当时未保存的原始 State。启动门改用原生 scontrol 的单份实时记录，只接受请求 JobId、RUNNING、明确正节点数与配置一致，查询失败／重复／非运行拒绝。RUNNING 零节点只允许原有有限等待，不依据环境变量填节点。sacct 继续是终态结算的唯一来源，控制器启动结果不提供计费秒数，不释放未知预留。既有字段及预算协议不变；测试明确令控制器运行而账表 PENDING／零节点，验证启动和拒绝结算两个边界。

## T050：目录锁的释放顺序

short-pseudo 的完整入口在 F4 合法恢复中因 campaigns.json.lock 已存在停止；现场是空锁目录，旧 Drop 先删除 owner 再忽略 remove_dir 的错误。没有保存底层删除错误，不猜测具体 NFS errno 或并发来源。释放须先验证当前 token 与唯一 owner 内容，再原子移动至同父目录、唯一 token 的退役路径；公共锁路径随之释放，退役清理失败不阻断后续。原子移动失败保留原 owner 现场，未知／额外内容不移动，不把清理改成删除未知锁。定向故障注入验证清理失败、新持有者保护和完整进程链。

显式终态回收仍须先核对原分配、唯一 owner、内容和身份，再复用同一原子退役／清理实现，避免第二条释放路径重新暴露删除 owner 后清目录失败的问题。原未知空锁不自动回收。
