## 决策、理由、备选与证据

### D01

**决策**：配置使用 serde 的封闭结构与 schema_version=1；共同路径在配置文件父目录解析，结构/PSEUDO/程序/显式环境脚本均 SHA-256 绑定。科学字段由后续契约定义后纳入同一解析器，未知字段报出字段路径。check 只读；prepare 使用同目录临时目录完整写入后发布，input-init.toml 写绝对绑定路径，并保存原结构名加 -init 的副本。执行前重新哈希，软链接目标改变使绑定失效。

**理由**：满足本项 Spec 对有效数据、隔离、失败传播与可复查证据的要求。

**备选**：沿用已有宽松配置、存在性判断或手工中间提交；因不能证明全部 FR/SC 而拒绝。

### D02

**决策**：使用单一 epwflow crate 的 foundation 模块，不修改已有 qf-config 的宽松语义。命令用 std::process::Command 和参数数组；环境脚本仅作为用户显式绑定的可信输入，用固定 Bash 包装并通过位置参数传递命令，不能 eval 配置文本。每个外部命令设置工作目录、输入、独立 stdout/stderr、超时和进程组，取消时终止所属进程组。

**理由**：满足本项 Spec 对有效数据、隔离、失败传播与可复查证据的要求。

**备选**：沿用已有宽松配置、存在性判断或手工中间提交；因不能证明全部 FR/SC 而拒绝。

### D03

**决策**：状态是版本化 JSON；状态写入为同目录临时文件、fsync、rename、父目录 fsync。协调锁采用排他锁目录，保存 owner/host/pid/boot/attempt；自动恢复不能删除未知锁，进程中断遗留锁须先核实无活动所有者与提交记录，再显式恢复。预算更新先取得共享账本锁，再取得运行锁，禁止反向锁序。记录修订号，读取损坏或新版本即失败。

**理由**：满足本项 Spec 对有效数据、隔离、失败传播与可复查证据的要求。

**备选**：沿用已有宽松配置、存在性判断或手工中间提交；因不能证明全部 FR/SC 而拒绝。

### D04

**决策**：预算使用整数节点秒与字节：总上限 28800 节点秒、107374182400 字节；每任务请求最多 7200 秒、1 节点、64 MPI。spent + unresolved_reserved <= limit。每个 allocation 只结算一次，sacct 的 step 行不重复计费，排队时间不计占用。Slurm ID 含 cluster，记录 AllocNodes/ElapsedRaw/State/ExitCode/Start/End；查询失败或缺终态保留预留。资源内运行须关联登记的 SLURM_JOB_ID，不能把同一 allocation 多次计费。

**理由**：满足本项 Spec 对有效数据、隔离、失败传播与可复查证据的要求。

**备选**：沿用已有宽松配置、存在性判断或手工中间提交；因不能证明全部 FR/SC 而拒绝。

### D05

现有源码：crates/qf-input/src/pw.rs、crates/qf-runner/src/lib.rs、qeflow/src/phonon_chain.rs、crates/qf-phonon/src/merge.rs、scripts/install-current.sh、scripts/verify-entries.sh。参考 external/epwpy 固定 b54bb53d4f5de665ed08958cb6194be8efdf645d。目标 QE 7.4.1 安装源码的 EPW/src/readin.f90、wannierization.f90、supercond_driver.f90、supercond_iso.f90、supercond_aniso.f90、io/io_supercond.f90 为版本适配事实来源；实际路径只记 docs/local。

源码声明 EPW 5.9 尚不等于实际程序身份。数值、节点兼容性和二进制读取必须用真实运行验证；网页工具本轮不可用，不能声称在线文档已核实。目标源码之外的新版本需独立适配。现有 qeflow 声子谱通过不能证明 EPW 输入完整。所有尚未运行的验收维持未完成。

### D09：三个程序与声子复用

依据用户最新明确选择，采用三个独立程序，不采用一个程序的三个子命令，也不新增第四个兼容程序。源码表明 qeflow 已保留 scratch，缺口在逐 q 数据生成与交付；因此提取现有实现为库、增加显式 EPW 数据归档，优于复制声子工作流。证据和细分职责见[整合契约](three-programs.md)。

## 最终交付的恢复职责

结果包清单发布与全部图表完成是两个时刻。工作流的已登记完成证据必须严格重验；尚未登记完成的最终交付应交由已有 F5 发布器进行身份核验和幂等接续，不能只因 manifest 已存在就直接执行最终完成验证而永久阻断恢复。相关主路径故障须由公开入口测试复现，见[连续执行设计](public-chain-validation.md)。

## F4 部分清单的恢复边界

T047 沿用 F4 已确认的显式恢复规则，详见[连续验证设计](public-chain-validation.md#t047原生超导部分清单续算)。采用 F4 统一发布证据校验：完整阶段可补登记，合法 partial 返回所属 Engine；不能简单忽略所有现有清单或捕获校验错误后强制重算。固定配置、来源、模式、搜索记录及产物身份仍是依赖，检查器不能替缺失的搜索文件建立新状态。零尝试模式通过当前 F3 原生角色重建绑定以核验空搜索，不从不存在的首次尝试推断来源。该决策不改变 F3 数据所有权、F4 搜索和预算协议。

## T048：oneAPI 初始化与严格执行

真实 PBE 作业在科学程序前因 oneAPI 读取可选变量触发 nounset 退出。生成脚本与内部提交脚本共用一个环境加载片段，仅 source 期间关闭 nounset，加载成功后恢复；保持 errexit，source 的非零退出继续阻断。不按单个变量补默认值，不修改显式绑定的用户环境文件或物理配置，不改变预算协议。证据包括实际生成／提交两类脚本的执行、含空格与引号路径、加载退出 17、严格选项恢复，以及本机真实 oneAPI 脚本加载；详见[0015 真实验证](../0015-epwflow-mgb2-real-validation/public-pbe-validation.md)。
