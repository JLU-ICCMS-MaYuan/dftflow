## 背景与目标

在消耗计算资源前发现配置、环境和数据问题；计算开始后能辨别提交、运行、数值验证与整体完成，防止重复任务和预算失控。F1 独立交付预检、输入绑定、执行与恢复基础；用明确产物契约的测试阶段验收，不将其等同完整超导流程。

### 需求结论与变更取舍

- 保留 Rust/Bash、三种 PH 模式、两种超导模式、固定物理参数和受限温度搜索的总体范围。
- 首版只接受非磁性、无 SOC、给定 μ* 的常规模型。结构优化、材料收敛和自动 Wannier 调参不进入 F1。
- 本次真实验收统一限制为每作业最多 1 节点、64 MPI、2 小时，同时最多 2 个运行作业，累计 8 节点小时，运行数据 100 GiB；参考、探测、失败和重试计入同一预算。
- 安装按较新的 0011 要求覆盖固定 current，默认不保留历史二进制；安装实现归 F5。F1 记录实际制品身份，不能把固定路径视作固定版本。

## 用户场景与验收

### US1：运行前检查输入与环境（P1）

**价值与优先级理由**：在耗费节点时间之前发现错误。

**独立验收**：从不同目录检查同一配置，解析到相同输入；检查过程不启动科学程序或提交作业。

1. 假如配置有效，当执行 check，那么报告配置与文件检查结果，并将未探测的运行版本明确标为未验证。
2. 假如存在未知字段、非法枚举、NaN、非正温度、错误路径或超额资源，那么报告具体字段和原因，返回失败。
3. 假如路径包含空格或命令符号，那么按路径/参数字面值处理，不拆错参数或执行其中的命令。

### US2：固定输入并准备独立运行（P1）

**价值与优先级理由**：避免提交后外部配置改变计算含义。

**独立验收**：prepare 生成输入快照和运行标识；相同输入重复准备不覆盖，修改外部输入不改变既有快照。

1. 假如运行目录为空，当准备，那么固定有效配置、结构和赝势来源，并显示实际工作与保存目录。
2. 假如目录已绑定其他输入或已有不明计算文件，那么拒绝覆盖，报告冲突。
3. 假如快照或复用数据被修改，那么执行前拒绝，不借用旧成功标记。

### US3：提交可追踪且不重复的任务（P1）

**价值与优先级理由**：一次提交的基础是可靠的提交记录与阶段依赖。

**独立验收**：使用独立进程模拟 Slurm 和有产物校验的测试阶段，证明并发启动与提交边界中断不会产生重复有效任务。

1. 假如两个入口同时提交同一阶段，那么至多一个有效提交，其余报告既有任务或冲突。
2. 假如调度器可能已收单但响应丢失，那么保存未决尝试，先核对，不能直接再次提交。
3. 假如程序退出零但产物校验失败，那么阶段失败，受影响下游不执行。

### US4：所有运行共用预算（P1）

**价值与优先级理由**：模式切换、参考计算和失败重试不能形成隐形超额。

**独立验收**：两个运行目录并发预留同一账本，恰好达到上限可接受，超过上限被拒绝；重启后统计不归零。

1. 假如所需预留超过剩余额度或可用存储，那么不提交新任务，也不删除数据释放额度。
2. 假如作业仍排队或状态未知，那么保留其预留；不能把排队时长计作实际节点时间，也不能提前释放未知作业的额度。
3. 假如手动参考作业未登记，那么验收不能宣称预算核对完整。

### US5：理解状态并安全续算（P1）

**价值与优先级理由**：用户能继续失败流程，而不是重做有效阶段。

**独立验收**：中断后重新启动，状态、来源与预算保持；有效完成项不再运行，失败项只在明确续算请求及额度允许时重试。

1. 假如查询不可用，那么显示状态未知，阻止重提和下游放行。
2. 假如已有任务活动，那么 resume 报告其作业号，不复制一份任务。
3. 假如科学阶段尚未接入 F1，那么 run/submit 明确报“阶段未实现”，不写工作流完成标记。

### 边界与异常场景

覆盖配置文件缺失、符号链接目标改变、程序文件替换、输出空间不足、损坏的状态/账本、孤立锁、作业取消/超时/失败、查询记录滞后、重复作业标识、部分提交失败，以及资源内运行与 Slurm 提交共用预算。无法可靠确认时保留现场并拒绝有副作用的继续操作，不猜测成功。

## 需求

### FR-001：独立入口与公开操作

新增 Rust epwflow 家族入口，提供如下公开命令；共同支持 --help，检查/状态支持 --json。以下 C 为配置路径，W 为已准备运行目录。

外部配置通过 `-c/--config` 显式指定，文件名不受限制。本机 MgB₂ PBE 示例使用 `-c inputepw.toml`，与同目录 qeflow `input.toml` 区分；`input.toml` 仍可作为其他独立目录中 epwflow 配置的文件名。名称不表示字段兼容，不能直接把现有 qeflow 配置传给 epwflow。固定快照仍为 `input-init.toml`。

| 命令 | 行为与副作用 |
| --- | --- |
| epwflow check -c C | 只读检查配置、输入、程序可访问性和已有版本证据；不启动科学程序，不提交，不创建计算目录 |
| epwflow prepare -c C | 检查并固定输入、运行身份与阶段计划；不执行科学计算、不提交 |
| epwflow probe -c C -s 或 -r | 显式探测程序启动与运行版本；-s 受控提交，-r 使用已登记资源，两者互斥，探测计入预算 |
| epwflow run -c C | 在已登记的现有计算资源内顺序执行有效阶段；不申请新资源 |
| epwflow submit -c C | 准备或核对已有绑定，安排依赖任务；返回提交/活动任务信息，不宣称计算完成 |
| epwflow status -w W | 读取本地状态；加 --refresh 查询调度器并核对、更新记录，不提交科学任务 |
| epwflow resume -w W -s 或 -r | 使用该运行的固定快照核对并续算；-s 与 -r 必须明确选择且互斥 |
| epwflow budget status/reserve/attach/reconcile | 查看共享账本；为独立参考预留、绑定实际作业、依据调度证据结算；不提供清零或绕过未知作业的强制退款功能 |

probe 的程序启动成功、运行版本匹配与科学计算成功分别报告。科学阶段未接入前，生产 run/submit/resume 必须返回明确不可用错误；测试阶段仅用于测试，不伪装成科学计算。

### FR-002：配置范围与严格校验

使用显式版本的 TOML 配置。共同字段分组为运行、结构/赝势、程序、资源、预算、QE/PH、Wannier/插值、超导/Tc；科学部分的具体字段由 F2–F4 定义，纳入同一最终配置契约，不能形成第二套相互矛盾的解析规则。

共同字段至少包含：schema_version、work_dir、outdir、结构文件、元素到赝势文件映射、程序路径与启动参数、PH 模式 nosplit/index/coords、求解模式 iso/aniso/both、节点数/MPI 进程数/时间限制、共享预算身份和账本位置。默认 PH 模式 index，默认 outdir ./tmp；求解模式和物理参数显式给出，不猜测材料参数。

拒绝未知字段、不支持版本/枚举、错误类型、非有限数值、非法范围及相互冲突设置；报告字段位置。不提供未经验证的任意科学参数透传来绕过模型和预算检查。资源只允许降低本次已授权上限。

### FR-003：路径与保存目录

用户填写的相对文件路径按配置文件目录解析，不依赖启动时工作目录；绝对路径优先，支持明确的用户主目录展开，不执行路径中的 shell 表达式。外部启动器和参数按参数列表处理，不以空白字符串拆分。

outdir 是保存目录基址，缺省配置值 ./tmp；按运行和阶段派生独立可写保存树，不能让 PH、电子态或各 q 点共享可写目录。check/prepare 必须展示派生后的实际路径，不能仅打印基址掩盖数据位置；F2 负责把对应实际路径写入科学输入。

### FR-004：输入绑定与指纹

prepare 固定有效配置、原结构名加 -init 的结构副本、赝势内容身份及程序身份，形成唯一运行标识。有效配置使用 input-init.toml；后续只读此绑定，不自动读取已改变的原输入。相同输入重复准备应幂等；冲突、损坏或篡改必须拒绝覆盖。

执行与复用前重新核对依赖指纹，不能把以前的 check 结果当作永久有效证明。复用来源保持只读，不以共享可写链接替代隔离。

### FR-005：环境证据分层

分别记录配置可解析、文件可访问、程序可启动、运行版本已验证。指定 QE 7.4.1 配套 EPW 为首个适配目标；目录名、配置声明和配套源码不能代替可执行证据。证据关联程序内容、探测环境与时间，文件替换后失效。

普通 check 不暗中探测或提交。显式 probe 以及完整提交流程中必要的受控探测必须计入预算；运行版本不匹配时阻断依赖任务。故意用于读取版本的探测退出行为单独判定，不能标成科学阶段成功。

### FR-006：阶段成功与依赖

阶段至少区分未准备、就绪、提交未决、已提交、运行、待验证、成功、失败、状态未知和因依赖/预算阻断；成功须同时满足执行结束、阶段数值校验和必需产物有效。工作流成功还要求所有必需阶段成功。

依赖关系必须无环。Slurm 成功依赖只承接已完成阶段校验的作业；校验失败的作业必须返回失败。不能把 JOB DONE、零退出码或队列消失单独作为数值成功。

### FR-007：严格提交与未知状态

使用原生 sbatch --parsable，核对退出码及唯一正整数作业号；如返回集群名一并保存。提交前持久记录本次尝试及预留；提交返回、作业号落盘和进程中断之间的任一步失败都必须可诊断。

用可关联的尝试身份核对调度记录。响应不明确、查询失败、查无尚未同步的记录或匹配不唯一时保持未决/未知，不自动重提。查询和等待有界，不依赖无限 safe_sbatch 重试，不占计算节点轮询等待其他作业。

### FR-008：并发与持久恢复

多个入口和多个运行共享账本时，提交、状态与预算更新须防并发覆盖，写入中断不能留下可被误认成功的半份记录。重启后读取已持久化身份，恢复已提交任务和预留。

未知锁或损坏记录不得直接删除后重来；给出诊断和恢复条件。已完成项只有在产物与依赖仍有效时才能跳过；确认失败项可由显式 resume 重试，每次新尝试都受预算约束。

### FR-009：节点时间与并发预算

本次验收只有一份持续账本，跨模式、运行目录、参考、探测和重试共享。提交前按节点数×请求时限预留；已结算消耗加未结算预留不能超过 8 节点小时。成功、失败、取消和超时都按实际占用结算，未核实的任务保留预留。

排队时间不计实际节点时间。不得重复累加同一分配的作业和步骤；资源内 run 使用已登记分配，整份分配只记一次。最多 2 个运行作业；并发控制须跨本次全部运行生效，不能依赖用户只开一个终端。

每作业上限 1 节点、64 MPI、2 小时。独立参考须先 reserve，再 attach 实际作业并 reconcile；提交响应丢失同样不得释放预留。不能通过换工作目录、复制配置、重新启动或自动新建预算身份重置本次限额。

### FR-010：存储与空间检查

将本次运行、必要快照、复制数据和参考输出纳入 100 GiB 统计；已有不可变公共软件和赝势库不重复当作运行输出。复制和新增阶段前检查实际占用、待执行任务的存储预留与文件系统可用空间；预计超过任一限制时拒绝开始。

运行中检测增长，达到上限停止追加并请求停止本流程的超限写入任务，保留现场和实际峰值；不删除用户数据。检查机制不能承诺跨文件系统的绝对硬配额，突发写入超限要如实报告为超限事件，不能记为预算验收通过。具体监测与停止机制在 Plan 中落实。

### FR-011：执行、参数与制品一致性

外部程序执行有明确工作目录、输入、日志、退出状态和资源上下文。路径及启动参数不经隐式 shell 求值；用户显式提供的环境脚本作为执行输入记录，不从配置文本猜测命令。

保存 epwflow 及科学程序的版本/内容身份；固定 current 路径的内容改变时重新校验，不静默沿用旧运行证据。安装操作由 F5 负责，现有工作流公开语义不变。

### FR-012：状态、错误与完成语义

默认终端输出简洁：状态、目录或作业号；错误包含阶段/字段、原因和可执行的下一步。JSON 输出带格式版本，区分命令操作成功、提交成功、阶段成功与工作流成功。

配置错误、环境不兼容、状态未知、预算拒绝、输入冲突和执行失败均返回非零。只读 status 可以成功返回“失败/未知”的工作流状态，但必须在结构化结果中明确显示；不能把查询命令退出零当作计算完成。

### FR-013：F1 独立交付与共享责任

F1 实现配置、输入绑定、状态、预算及阶段执行契约，F2–F4 提供科学输入与数值验证器，F5 提供汇总绘图和最终安装。F1 测试使用独立进程、可检查产物和受控失败的测试阶段；不得为通过测试而绕过实际提交/状态/预算边界。

F1 的真实环境探测能力、被模拟验证的执行能力和尚未验证的科学能力分别列证据。全部详细 Spec 文档质量门通过前不实施业务代码。

### 关键实体

- **运行绑定**：唯一运行身份、固定配置/结构、赝势与程序身份、工作与保存目录、所用预算身份。
- **阶段及尝试**：阶段身份、依赖、输入指纹、尝试身份、资源、作业身份、执行/数值状态、产物证据和失败原因；同一尝试不能对应多个未经解释的活动作业。
- **环境证据**：检查层级、程序身份、环境、版本、时间及诊断；失配后不可继续复用。
- **预算账本**：本次授权上限、全部预留、实际用量、未核实作业、存储占用和参考登记；更新不因进程退出而丢失。
- **完成证据**：必需产物、数值验证结论及对应依赖身份；不是单独一个“已完成”布尔值。
