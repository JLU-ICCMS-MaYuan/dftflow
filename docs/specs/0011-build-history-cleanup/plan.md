# 固定安装路径实施方案

1. 新增 install-current.sh，完整复制五个程序到同文件系统临时目录，验证所有入口；安装锁防止并发更新，退出清理临时目录。
2. 验证后逐文件 mv 原子替换 current/bin，再统一入口；入口备份改为显式开启。
3. 从已验证的本机兼容制品迁移，不重新编译、不改变 ELF 私有加载器。独立工具迁到 tools/qf-gen-dyn0/current/bin。
4. 无活动作业时，替换项目内已发现 .sh 中的 versions/<旧版本>/bin 路径，记录旧新文件哈希；删除旧安装目录。
5. 更新文档并验证重复安装和无效输入保护。更新不是五程序事务切换；不再承诺旧脚本固定使用提交时的程序版本。

本次清理不全量遍历其他材料 work 目录；其中未发现的旧脚本若引用版本目录，复用前需重新生成。这个已知边界不能作为全盘无旧引用的证明。

## 仓库 bin 分组安装

1. 新增 `scripts/install-bin.sh SOURCE_BIN [BIN_ROOT] [DYN0_BINARY]`，默认目标为本仓库 `bin/`。复用现有兼容入口安装与验证，不复制各模块的命令列表。
2. 在目标根目录建立安装锁和临时副本，先核验八个程序与全部 54 个入口；显式提供独立 dyn0 时一并核验。按真实程序归属分组，兼容命令使用组内相对软链接。
3. 替换前核对全部目标目录和文件，拒绝目录或模块目录软链接冲突，随后逐文件原子替换。退出清理安装锁与临时文件；不承诺整组事务更新。
4. 本机从已有的五个已安装兼容制品、三个冻结 EPW 制品及独立 dyn0 复制，不重新编译、不更改 ELF 加载器，不切换 `~/.local/bin`。来源及哈希留 `docs/local/`。
5. 新运行使用分组路径；已有生成脚本的绝对程序身份保持不变，旧程序不删除。状态查询与数据检查可使用同字节的新副本；恢复与重新生成的身份约束分别说明，不自动提交。
6. 安装的隔离回归覆盖重复更新、缺失或损坏程序、目标冲突与全部入口启动，再同步 README、测试辅助入口和 Overview。
