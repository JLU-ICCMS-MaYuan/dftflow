# PBE 粗网格 EPC 非有限值的源码核查

对应本地 Issue 0012 的 T061、0015 的真实 PBE 验收。完整科学验收仍未通过；本记录没有把源码缺陷直接当成已证明的 NaN 唯一根因。

## 已确认的现场

公开第二阶段的原生作业 1297009 正常退出，但 `epmatwp` 的 179550 个 float64 值全部为 NaN，生产有限性检查拒绝发布 F3。两个输入 `dvscf_q*` 共各 933120 个 float64 值均有限，矩阵文件尺寸与 5 个 Wannier 函数、9 个模式、57／7 个实空间向量相符。

局域化 500 次未收敛是另一个已确认问题；有限 spread 和正常退出均不能代替收敛，也不能证明它造成了 EPC NaN。固定窗口、迭代次数、赝势与网格未调整。

## 已确认的外部源码缺陷

本轮直接读取实际安装的 EPW 5.9 源码，并核对可执行文件中的 `dvscf_read` 符号与调用顺序，没有只依赖仓库中的另一个版本。

1. QE `PW/src/setup.f90` 在 `ecutrho/ecutwfc > 4` 时设置 `doublegrid`。本次 320/40=8；原生输出给出稠密 FFT 36×36×40=51840 点、平滑 FFT 24×24×24=13824 点；粗 EPC 例程要求每 pool 一进程，不能把这两个不同大小解释为 MPI 分片。
2. `EPW/src/ep_coarse.f90::dvscf_read` 的输出数组按稠密网格声明，临时数组按平滑网格分配；插值后执行整数组赋值，维度不相等。使用真实网格尺寸的最小 Fortran 检查报 `Array bound mismatch ... (51840/13824)`。
3. 该赋值还发生在 `newdq2` 之前。后者使用稠密 FFT 计算 ultrasoft 增广积分，需要原始稠密响应；而下游 `ep_coarse_compute` 按平滑网格的首维和扰动步长读取。仅修改赋值切片仍不能同时修复积分输入和多个扰动的内存排列。

两份响应势本身有限，加上上述确定的维度／调用顺序错误，使双 FFT 分支成为 NaN 的强相关候选。原生过程没有保存变换前的 EPC 中间矩阵，因此尚未证明它解释了全部非有限值；须用隔离修复程序做同输入对照。

## 已准备但尚未应用的修复

修复提案将稠密响应保留在专用临时数组，先调用 `newdq2`，再插值到独立的平滑网格输出；两个调用点均按平滑首维分配。非双网格情形直接复制相同大小的响应。原生赝势、cutoff、k/q 网格、窗口、收敛门与并行布局不变。

从实际源码提取的原例程在独立契约检查中退出 71，检测到稠密响应被提前转换；提案通过 12 组双／单网格、1／2／3 个扰动、2 自旋通道和时间反演标志检查。FFT 和 MPI 在该检查中为数据／顺序替身，不能当成真实物理验证。

补丁、原始／提案例程、检查程序、退出日志、二进制反汇编和哈希清单位于忽略目录 `test_auto/MgB2/local_run/010-public-pbe/double-grid-audit/`；补丁为 `epw59-dense-smooth.patch`，清单为 `proposal.json`。实际安装与仓库外部源码均未修改，未构建新的 QE／EPW，未提交新 Slurm 作业，预算仍为原账本累计 3140 节点秒。

用户此前撤回过外部科学程序构建，因此隔离构建与最多一个固定粗网格对照已单独询问授权。答复前不执行依赖步骤。即使 EPC 有限性得到修复，原局域化收敛、独立插值质量、细网格与两个 Tc 仍须逐项验收；不得自动提高迭代或扫描参数。
