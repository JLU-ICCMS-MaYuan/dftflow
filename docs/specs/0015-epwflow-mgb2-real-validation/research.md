# 研究与取舍

## 已核查事实

- 真实 CLI submit/run 直接拒绝，--until 缺失；已保存实际退出码，不仅搜索字符串。
- 41 项测试通过，但 F3 fixture 自己写 epw.out、fine_frequencies.dat 等简化数据，并用没有电子态和 q 点的 F2 清单触发成功；不能证明目标 EPW 格式适配。
- F3 频率公式造谱及 F4 经验公式可从生产 scheduler 调用链直接定位，不是仅存在于测试中的辅助函数。
- 目标安装的 EPW/src/readin.f90 没有 energy_reference/seedname 输入名，却有 nkf1/nqf1。生产输入生成器写了前两项并将细网格写成 nk1/nq1；必须按完整目标 namelist 逐项适配，不只修改一个拼写。
- 现有三模式日志、dyn0、响应势和保存数据已盘点；旧计算没有新 manifest，不能直接声称导入可用。

## 决策

1. 先复用三模式已有数据，避免重跑兼容 SCF/PH。备选从头重做全部会增加成本且绕开用户要求的复用验证，拒绝作为默认路径。
2. 冒烟与科学一致性分开：启动成功可以形成第一份证据，但不能关闭 0015 或上游 Epic。
3. 只修复原契约；若需大范围补齐缺失能力，先明确职责并交接。不能把重写科学求解器当 debug，也不能把经验模型输出冒充 EPW。
4. 旧 41 项测试保留作回归，增加实际格式和 CLI 失败场景。测试必须拒绝空清单、合成谱、缺收敛及未知预算状态。
5. 已授权预算不因 0015 新编号而清零；与本活动无关的 SiP2 作业不凭名字含 EPW 混入统计。尚不能证明的历史消耗保持未知。

## 证据边界

当前没有本次新增真实作业。文件存在、源码版本、模拟退出零分别不足以证明可执行版本、数值收敛和物理正确。真实目标路径与原始查询仅存 docs/local/0015-epwflow-smoke/。
