# 0017：仓库构建与唯一程序入口实施计划

**输入**：[规格](spec.md)、[研究](research.md)、[Issue](issue-draft.md)。用户明确授权合并后实施。

## 结构与职责

- `scripts/build-native.sh`：加载本机依赖配置，平台选择、统一 Cargo 缓存、识别交付操作、收集本次制品并调用发布。
- `scripts/product-layout.sh`：唯一产品与兼容命令清单，供安装、验证和发布复用。
- `scripts/publish-artifacts.sh`：准备本次制品快照，Linux 必要兼容打包，调用分组发布，记录源与发布指纹。
- `scripts/install-bin.sh`：支持显式产品集合，预检全部目标冲突与启动，按模块逐文件替换；共享锁阻止并发发布。
- `scripts/env.sh`：Bash/Zsh 仅公开七家族路径，优先于旧入口且重复加载幂等。
- `bin/.build/<平台>/`：Cargo 缓存、测试 harness 和原始制品；`bin/.native/<平台>/`：私有依赖；`bin/.history/0017/`：按原哈希保留的历史二进制。

## 实施顺序

1. 合并全部原文与调查、更新 FR/SC 和设计任务，删除重复目录并修复引用。
2. 建立共享清单、部分制品发布和 Cargo 自动发布链；非 build 操作不发布，失败在替换前拒绝。
3. 隔离验证完整／部分发布、增量 fresh 制品、失败、路径含空格、库构建和非交付操作；适配独立工具与 Linux 发行脚本，退役旧安装器。
4. 迁移本机 native 依赖并更新元数据和忽略配置；构建测试使用新前缀，实际发布等待活动作业结束。
5. 完整构建九个产品，连续两次构建与全部入口核验；执行 workspace、独立工具及受影响脚本回归。
6. 逐项迁移历史测试二进制到私有归档并写清单；现用脚本指向家族目录，历史证据不回写。
7. 清理自有旧入口，核验旧根不可访问时启动和构建；删除旧根，再次验证不重建。真实启动文件按原约定不自动编辑，说明用户加载方式。
8. 更新 README、Overview、工具和手册；记录通过、未执行和现场证据，精确提交，不推送。
