# 新需求：简化 QE／EPW 目录、读取当前配置续算、增加并行检查

## 1. 目标与需求记录

按你的意思：**修改 `input.toml` 后执行提交命令，直接按新参数计算。** 程序自动复用仍然适用的结果，只重算需要更新的步骤；遇到参数错误、空 pool 或活动任务冲突才停止。

使用 `big-project-issue-manager`、`big-project-spec-runner` 新建独立 Feature。沿用项目“本地需求与 Spec 落档、线上 Gitee 由用户管理”的约定，暂定编号 **0018**，落档时检查编号是否被占用。完整保存本次需求原文、澄清结果、设计、任务及验收标准，关联既有 QE／EPW Feature。

## 2. 目录和计算阶段

新布局直接放在本例 `run/` 下：

```text
run/
├── input.toml
├── POSCAR
├── pp/
├── KPATH.in
├── submit_all.sh
├── 1.qe-scf/
├── 2.qe-nscf/
├── 3.qe-electronic/
│   ├── qe_eband/
│   └── qe_eledos/
├── 4.qe-phonon-nosplit/          # 或 coords、index
│   └── save/
├── 5.epw-wannier/
├── 6.epw-coarse/
├── 7.epw-fine/
├── 8.epw-superconductivity/
│   ├── iso/
│   └── aniso/
└── .epwflow/                    # 内部状态与历史记录
```

- **输入与脚本同目录**：每个实际计算目录都有对应的原生输入、`submit.sh` 和日志；分 q、分温度等子任务同样遵守。批量提交脚本只负责组织依赖，放在这些目录的上层。
- **第 1～4 步**：复用 qeflow 的输入、执行及后处理能力；电子能带与 DOS 保留 `qe_eband`、`qe_eledos` 名称。PH 复用第 1 步的 SCF，不另做一套 SCF。
- **第 4 步**：同时支持 nosplit、coords、index 的 EPW 数据归集，真正生成可校验的 `save/`，包括动力学矩阵、响应势和 phsave。
- **第 5 步**：独立进行 Wannier 拟合，输出与 QE 对比的电子能带、总电子 DOS；复用原生 Wannier90／postw90 及现有绘图能力。
- **第 6 步**：复用第 5 步已验证的 Wannier 变换，计算粗网格电声耦合，并输出电子、声子对比图及质量报告。
- **第 7、8 步**：分别负责细网格 EPC／α²F／λ，以及超导求解。此前暂缓的严格元素／轨道投影仍保持暂缓。

编号帮助阅读；实际执行依赖由程序管理。

## 3. 配置读取、续算与命令接口

**根目录的 `input.toml` 是日常修改入口。** 各阶段的原生输入由它生成，不要求用户维护多份 TOML。

| 修改内容 | 默认处理 |
|---|---|
| MPI、pool、分区、时限 | 更新待执行任务的提交设置，复用相容的科学结果 |
| EPW `nqf`／`nkf` | 更新细网格及依赖它的超导结果 |
| Wannier 能窗、投影、函数数量 | 更新 Wannier 及依赖它的 EPW 结果 |
| QE 粗 q 网格，即 EPW `nq` 对应的数据 | 更新 PH、声子后处理及相关 EPW 阶段；相容的 SCF、NSCF、Wannier 保留 |
| 结构、赝势、截断能等上游参数 | 从最早受影响的步骤开始更新 |
| 仅绘图设置 | 只更新相应后处理和图像 |

实现采用每个步骤的参数及上游产物指纹判断复用，替换当前“整套固定配置必须相同”的限制。原生重读文件另外检查格式和并行布局，不能把不相容数据当作可复用结果。

保留三个公开程序，增加阶段选择：

- `epw_phonon`：管理第 1～4 步。
- `epw_wannier --stage wannier|coarse`：选择第 5、6 步；默认完成两步。
- `epw_superconductivity --stage fine|superconductivity`：选择第 7、8 步；默认完成两步。
- `-s` 读取当前配置并提交；不带执行选项只生成输入和脚本。`--resume` 保留为显式续算入口，也读取当前配置。

每次提交保存该次参数和脚本，保证排队期间修改配置不会改变已提交任务。历史快照用于追溯，不再决定以后提交使用什么参数。活动或终态未知的同阶段任务不能重复提交。

## 4. 并行预检与旧数据衔接

并行检查覆盖**生成输入、提交前、脚本启动前**，手工 `sbatch` 也不能绕过。

- 核对 Slurm 任务数、MPI 启动数量、pool／image 设置是否一致且受支持。
- 粗网格 k 点数核对实际 NSCF 数据；细网格按该次执行使用的网格检查。
- pool 数超过可分配 k 点数时，打印网格、k 点数、MPI 和 pool 数，解释会出现空 pool，然后非零退出。
- 当前 EPW 单 image 路径要求每 pool 一个 MPI 进程，明确检查该约束；QE 使用自身的并行规则。
- 不自动修改用户的物理网格或并行设置来绕过错误。

为当前旧 `epwflow/work/` 提供一次性导入：核验原清单、参数及哈希后，将可复用数据物化到新布局并建立新清单，保留原来源记录。**已有 QE 不因目录改版而重算，旧计算现场不删除、不改写。**
