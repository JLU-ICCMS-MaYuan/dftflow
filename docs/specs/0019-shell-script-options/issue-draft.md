# 0019：移除仓库脚本的自动严格选项

唯一类型：`type:maintenance`。沿用仓库本地 Issue 草稿约定；0019 是本地编号，线上 Gitee 由用户维护，未创建或关闭线上 Issue，远程链接待验证。

## 原始需求记录

> 所有的脚本都不要加这个东西“set -euo pipefail“，这个仓库里面所有的 flow 的提交任务的脚本都不要加，新建一个 issue 和 spec，然后完成。

> 全部移除，包括构建、安装和自测脚本

## 目标与范围

所有 flow 的脚本生成器、仓库跟踪的 Bash 脚本及测试生成的脚本均移除自动开启的严格选项，不拆成其他 `set` 写法重新开启。去掉 EPW 环境加载后的 `set -u`。关键步骤依赖显式退出码处理，保持环境加载、安装校验、构建和自测失败的可见性。

## 验收与关联

- 生成脚本及仓库跟踪的可执行脚本不再包含严格选项注入。
- 脚本语法检查、相关 Rust 回归及安装失败保护验证通过。
- 原始科学结果、冻结运行脚本和历史验收记录保留；本需求不提交科学作业，不切换安装。
- 独立维护项，无父 Issue、无阻塞依赖；关联 0006、0008、0017、0018 的脚本实现。
- 详细需求见 [Spec](spec.md)，技术验收见 [验收记录](acceptance.md)。
