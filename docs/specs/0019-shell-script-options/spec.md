# 0019：仓库脚本不自动开启严格选项

日期：2026-10-20。类型：维护。关联 [本地 Issue](issue-draft.md)，线上链接待用户创建后核验。

## 原始需求记录

> 所有的脚本都不要加这个东西“set -euo pipefail“，这个仓库里面所有的 flow 的提交任务的脚本都不要加，新建一个 issue 和 spec，然后完成。

> 全部移除，包括构建、安装和自测脚本

## 背景与目标

EPW、Wannier、QE、substitution 和共享运行库会在脚本中注入严格选项；构建、安装和自测脚本也存在同样设置。用户要求统一移除，避免外部环境加载及执行受隐式 shell 选项影响。

## 用户故事与验收场景

### US1（P1）：各 flow 生成普通任务脚本

给定任一脚本生成入口，生成阶段或聚合提交脚本时，不插入严格选项，也不在加载环境后重新开启。环境读取未定义的可选变量可以正常继续；加载返回非零时显式退出。

### US2（P1）：构建、安装与自测使用显式失败判断

给定有效输入，脚本正常完成；给定缺失或不能启动的程序，安装返回失败且不以成功消息掩盖错误；自测断言失败时返回非零。

## 功能要求

- FR-001：所有 flow 的生成脚本不得自动加入 `set -euo pipefail` 或等价拆分选项。
- FR-002：所有仓库跟踪的 shell 脚本与测试脚本模板遵循同一规则，包括构建、安装和自测。
- FR-003：环境加载、目录切换、关键外部命令及自测断言通过显式退出码判断处理失败。
- FR-004：保留原有 CLI、Slurm 参数、科学输入和结果判定，不修改冻结历史运行现场。

## 成功标准

- SC-001：对全部跟踪脚本和生产生成器审计，自动严格选项命中数为零。
- SC-002：修改的 shell 脚本通过 `bash -n`；相关 Rust 回归通过。
- SC-003：实际生成 EPW 脚本允许未定义可选变量，环境返回 17 时退出 17；安装成功与失败保护自测通过。

## 边界、异常与依赖

用户配置的 Slurm header 按原样保留；不擅自过滤用户主动写入的 shell 命令。已经冻结并记录哈希的计算脚本作为历史证据保留，新生成脚本采用新规则。外部环境脚本本身的设置由用户管理；external/ 第三方子模块属于独立上游仓库，保持其内容与指针不变。无新依赖、无数据模型变更、无新接口；单一维护项不依赖科学计算验收。

## 范围外

不部署默认命令、不重提作业、不改科学参数、不覆盖忽略目录的历史来源，不重写既往验收记录。
