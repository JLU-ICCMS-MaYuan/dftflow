# 0022：简短 Slurm 日志文件名的设计与验收

## 需求与边界

需求及用户实施授权见 [0022](issue-draft.md)。自动生成的日志指令只写文件名，日志留在相应脚本目录；保留各入口的命名、作业号占位符、资源、科学参数、依赖、预算和恢复保护。用户自定义 Slurm header 不改写。

## 实现

| 路径 | 日志文件名 | 目录控制 |
| --- | --- | --- |
| EPW 编号阶段及电子子目录 | `slurm-%j.out`、`slurm-%j.err` | `#SBATCH --chdir` 固定各脚本目录 |
| EPW 三程序的旧生成入口 | `<阶段>.%j.out`、`<阶段>.%j.err` | 固定 `epw-state/generated/`；正文仍回计算工作目录 |
| EPW 旧工作流内部尝试 | `%j.out`、`%j.err` | 固定 `epw-state/slurm/`；删除 `sbatch` 命令中覆盖日志的绝对路径参数 |
| EPW 通用阶段后端 | `slurm-%j.out`、`slurm-%j.err` | 固定脚本目录，正文显式回原科学工作目录 |
| Wannier90 默认 init／post 脚本 | 保留 `slurm.out`、`slurm.err` | 默认 header 增加固定目录；正文使用生成时确定的实际目录 |

EPW 共用 `foundation/slurm.rs::log_directives()`，集中生成文件名和目录声明，避免不同入口分别拼接日志绝对路径。Wannier90 的 init／post 共用默认 header 选择函数；用户提供的 header 保持原样。其他 flow 的 header 来自用户配置，没有发现另一处程序自动拼接长日志路径的生成代码，因此不擅自重写用户配置。

目录使用现有的引号处理，覆盖空格和单引号。Slurm 在脚本正文执行前打开日志，单靠正文 `cd` 无法保证日志位置；默认工作目录来自提交进程，可通过 `--chdir` 设置。依据为 [Slurm 官方 sbatch 文档](https://slurm.schedmd.com/sbatch.html)。Wannier90 正文也不再把 `$0` 的 spool 目录误当成计算目录。
