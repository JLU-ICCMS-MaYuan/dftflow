## 原始需求记录

> 我希望你再新建一个 issue 要求：脚本生成的 slurm 脚本不要在 --output=和--error=后面写这么长的绝对路径，可读性非常差，反正你也是要把这些日志输出在提交任务脚本所在的目录下，没必要写这么长，只需要定义好名字就行。
> 而且为什么我在提任务的脚本里面会看到 || exit $?，我觉得不需要这个符号。而且我希望你能简化一点。
> 使用 issue 和 spec 来完成。

> 简化写法，仍在关键步骤失败时停止（推荐）

## 目标与范围

使各 flow 自动生成的 Slurm 作业脚本及其总提交脚本易读：日志指令只写文件名，日志仍保存在对应作业脚本所在目录；移除自动生成的 `|| exit $?`，减少重复检查和不必要的包装。

```bash
#SBATCH --output=slurm-%j.out
#SBATCH --error=slurm-%j.err
```

保留现有阶段命名、作业号占位符、标准输出与标准错误的区分。覆盖生成器与程序提供的提交路径，避免 `sbatch` 命令参数重新覆盖成长路径；跨目录提交也须验证日志位置。

## 当前依据与需求结论

- EPW 的 `workspace.rs::script()`、`workflow.rs::generate_phase_for()` 写入日志完整路径；后者所在模块的另一提交路径还在 `sbatch` 参数中写入日志完整路径。
- EPW 的环境加载和目录切换，以及 QE、共享运行库的部分生成命令包含 `|| exit $?`。它表示上一条命令失败时结束脚本，源于 0019 移除自动严格选项后保留失败传播的实现选择。
- **用户已明确**：简化写法，保留关键步骤失败时停止。删除后缀不能变成静默继续，也不能吞掉原始非零退出码；已有程序负责的失败处理不再由 shell 重复包装。
- 简化原则为直接执行现有流程、去掉重复包装；不另加通用 shell 框架，也不恢复 `set -euo pipefail` 或等价严格选项。
