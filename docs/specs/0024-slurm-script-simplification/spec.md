## 用户场景与验收

### US1（P1）：直接读懂日志文件名及位置

用户查看任一新生成的 Slurm 脚本，可以直接看到简短的标准输出、标准错误文件名。优先级理由：这是原始需求明确指出的可读性问题。

**独立验收**：分别通过公开入口、总提交脚本及其他目录的直接提交，核对输出文件名和日志实际目录。

1. **假如**生成阶段作业脚本，**当**查看日志指令，**那么**值中没有目录前缀，且保留阶段区分及作业号占位符。
2. **假如**从其他目录提交，**当**作业启动并输出，**那么**两类日志均位于该作业脚本所在目录。

### US2（P1）：提交脚本只保留必要步骤

用户能够按顺序读出环境准备、工作目录及执行入口，不必反复阅读 `|| exit $?` 和重复包装。优先级理由：这是本次新增的明确要求。

**独立验收**：检查各受影响 flow 的实际生成脚本，运行正常路径并核对命令顺序及最终退出结果。

1. **假如**生成作业或总提交脚本，**当**查看自动生成部分，**那么**不出现 `|| exit $?`，也不注入严格选项。
2. **假如**正常输入，**当**运行新脚本，**那么**按原有顺序执行必要步骤，不因去掉重复包装而漏执行。

### 边界与异常场景

- 目录含空格时，日志位置、环境路径及执行命令仍被正确处理。
- 日志目录由提交时语义决定，不能仅以正文里的 `cd` 证明日志会输出到脚本目录。
- 环境加载、切换目录、计算及提交失败时，脚本停止并保留原始非零退出码，不执行后续依赖步骤，也不得把失败结果发布为有效计算结果。
- 总提交脚本组织多个阶段时，日志归属于各阶段作业脚本，保留阶段身份与重复提交保护。
- 用户自定义 header 与冻结脚本不自动重写；发生显式用户覆盖时应区分用户内容与生成器默认行为。

## 需求

- **FR-001**：各 flow 自动生成的 Slurm 日志指令必须只包含文件名，不含绝对或相对目录前缀。
- **FR-002**：通过程序提供的提交入口、总提交脚本和跨目录直接提交时，日志必须保存在相应作业脚本所在目录；程序传入的参数不得覆盖回长日志路径。
- **FR-003**：保留标准输出、标准错误区分及现有必要的阶段标识和作业号占位符，避免作业间日志覆盖。
- **FR-004**：作业及提交脚本的自动生成部分必须移除 `|| exit $?`；不得引入 `set -euo pipefail`、等价拆分选项或更复杂的通用包装框架。
- **FR-005**：脚本应直接表达必要步骤，删除重复检查及无实际作用的包装，保持正常路径的命令顺序、参数、阶段依赖与重复提交保护。
- **FR-006**：环境加载、目录切换、计算及提交等关键步骤失败时，脚本必须停止并保留原始非零退出码，不继续后续依赖步骤，不得报告成功计算。
- **FR-007**：本次变更不得自动改写用户 header、冻结运行现场、第三方源码及已有科学结果。

## 成功标准

- **SC-001**：各受影响生成入口的日志指令及程序传入的日志参数中，目录前缀命中数为零；覆盖 FR-001～003。
- **SC-002**：公开入口、总提交、跨目录直接提交及带空格目录四类场景的日志位置均满足 FR-002。
- **SC-003**：自动生成部分的 `|| exit $?` 及自动严格选项命中数为零，正常路径顺序与退出结果符合预期；覆盖 FR-004～005。
- **SC-004**：环境、目录、计算及提交的四类非零退出场景，均以原始退出码结束且后续依赖步骤未执行，不误报成功；覆盖 FR-006。
- **SC-005**：受影响脚本语法检查及相关行为回归通过，历史现场和来源数据不变；覆盖 FR-005、FR-007。
