## 目标与用户价值

EPW 三个公开程序不再依赖 `.epwflow/` 或其他隐藏目录保存运行状态。用户通过普通 `ls` 就能找到阶段状态、提交记录和恢复所需文件；删除某个编号阶段目录后，程序能识别该阶段需要重建，不要求用户查找并手动清理另一处隐藏成功记录。

运行状态仍须支持正确复用、排队配置隔离、重复提交保护和预算结算。取消隐藏存放不等于取消必要校验，也不能仅把 `.epwflow` 改名后保留本次删除目录即报错的行为。

## 当前源码依据

- `epwflow/src/foundation/stages.rs::receipt()` 将阶段完成回执写入 `.epwflow/steps/<stage>.json`，独立于编号计算目录。
- 同文件的 `reusable()` 在回执及配置匹配时调用 `Completion::verify()`；后者逐项校验产物身份，缺失文件的错误直接向上传播，没有将其归为需要重建的阶段。
- `epwflow/src/foundation/workspace.rs` 将活动任务、尝试、请求、配置快照、锁和归档写入 `.epwflow/`。因此只修改完成回执的存放位置不足以达到目标。
- `epwflow/src/foundation/layout.rs` 还将布局标记、QE 数据交付清单、粗网格和插值交付记录等映射到 `.epwflow/`；旧 `workflow.rs` 也保留隐藏状态路径，实施时须核对实际入口和兼容路径。
- 上述代码路径支持用户描述的故障机制；本轮没有读取或改写现场隐藏记录，没有重新执行删除操作、调用已安装命令复现或提交计算。已安装程序与源码版本是否一致仍须在实施验证时核对。

## 实施范围与需求结论

1. 覆盖 `epw_phonon`、`epw_wannier`、`epw_superconductivity` 的生成、状态查询、提交和恢复，以及它们调用的工作区、交付和兼容路径。
2. 阶段完成记录放在对应的可见编号阶段目录中；确需跨阶段保存的提交、配置快照、锁、历史与预算关联记录放在明确可见的位置。具体文件名、共享目录名及旧格式兼容办法在后续设计中确定，不预设另一套通用状态框架。
3. 阶段目录已删除或必要产物缺失时，将该阶段判为不可复用，并按依赖使下游旧交付不可复用；上游完整且配置相容的结果继续复用。目标阶段的生成与提交不得因旧成功记录引用缺失文件而直接以本次 `input_conflict` 终止。
4. 区分阶段产物缺失、内容被修改、记录损坏和活动作业状态未知。不能将所有校验异常都吞掉当作重新运行；遇到无法安全恢复的情况，明确说明阶段、原因和可执行的处理方法。
5. 旧工作区须有明确的识别、兼容或迁移流程；正常运行不再持续依赖隐藏状态。不得静默丢失历史消费、未结算预留、提交身份或科学数据，也不得自动删除用户的旧隐藏目录。
6. 阶段被删不代表正在排队或运行的作业已取消；仍须防止活动任务或未知提交重复执行。状态查询保持只读，迁移和重建操作应清楚可见。

## 范围外事项

- 本项聚焦 EPW 管理的运行工作区，不扩展成所有 flow、第三方软件或整个仓库的隐藏文件清理。
- 不改变三个公开程序、编号阶段的用途、科学参数、质量标准或既有预算；不取消文件完整性与依赖校验。
- 本轮不实施生产代码、不删除或迁移现场文件、不提交科学作业、不切换默认安装、不推送。
