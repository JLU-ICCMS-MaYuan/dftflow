# 实施方案

## 目录与职责

- `epw-state/` 保存 layout、active、attempts、requests、history、logs、slurm、旧工作流控制记录和跨阶段交付清单；只改存放位置，不复制执行引擎。
- 每个编号阶段使用 `completion.json`；第 3 阶段原生回执放 `3.qe-electronic/receipts/`。后处理回执跟随所属阶段。科学证据枚举排除回执，避免记录自身哈希。
- 路径沿用 layout 唯一映射；阶段目录是否可复用由科学键、依赖及实际文件共同判断。

预算注册表默认使用可见的 `~/epwflow-state/`；显式环境覆盖保持优先。首次写入新默认注册表时承接旧默认位置的 campaign 绑定，防止换目录绕过原账本。

## 缺失与冲突

仅 `NotFound` 属于可重建；不得使用 catch-all 将任何错误转换为缓存未命中。先检查记录结构及存在的输出身份，再判缺失。生成与执行共享判定；重新生成输入时不能因旧 requests 相同而跳过缺失输入。阶段产物失效要使依赖缓存键不再有效，即使重算得到相同字节也不能错误复用旧下游。

## 一次性旧状态处理

新增显式 `--migrate-state`。平常发现旧 `.epwflow/` 且无迁移结果时给出明确命令，不自动写入。迁移仅支持 numbered：拒绝活动/未知提交、锁和进行中的导入；复制旧状态到可见历史并校验前后文件集合，不删除或改写原目录。保留内容未改变且不依赖隐藏文件的 SCF、NSCF、PH、Wannier 及电子原生回执；有隐藏路径绑定的粗/细交付和旧尝试仅作归档，后续须重建，不能直接改写哈希冒充原交付。保留 QE 交付清单以继续复用已核验 PH。迁移输出明确列出复用与重建阶段，不启动作业。迁移事务未完成时禁止正常运行，避免半迁移误判为新现场。
