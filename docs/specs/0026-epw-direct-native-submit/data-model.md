# 0026 数据与接口契约

## 原生任务

`epw-state/native-jobs/<命令键>.json` 保存同一阶段尝试中的实际命令、目录、输入、程序／结构／赝势／环境身份、唯一脚本及哈希、预算预留、作业号、退出码和原生日志身份。`history/<任务号>.json` 保留逐次提交记录，`native-active.json` 指向当前任务。

状态顺序为 `prepared` → `submission_pending` → `submitted` → `awaiting_validation` → `validated`。无法确认提交回执时进入 `unknown`，禁止重提；原生非零退出或科学核验失败进入 `failed`，须显式恢复。科学阶段继续使用既有完成收据，不用原生任务的调度状态代替科学成功。

脚本位于实际科学工作目录，名称为 `submit-<任务>-<任务号>.sh`；`submit.sh` 是便于阅读的当前副本，正式回执绑定唯一脚本。日志为同目录 `native-<任务号>-<作业号>.out/.err`；由作业外命令归集为原科学校验器所需的日志及退出码文件。

## 阶段推进

`epw-state/native-progress/<阶段>.json` 保存科学键、阶段尝试号及运行／失败／完成状态；在多次公开命令之间复用同一次准备现场。QE 与 Wannier 准备函数在已有原生记录时直接进入归集，不重复复制保存树。插值与独立参考复用原持久检查点；Tc 在原搜索记录中归集同一次尝试，暂停不新增计数。

`native-plan.json` 包含目标、当前原生任务、已核验及待完成阶段和手动推进提示。它是准备结果，不是自动调度服务或独立行动状态来源。

## 命令接口

三个公开程序的 `-s` 对编号工作区执行校验并推进；一次至多提交一个任务。`--resume -s` 允许重试明确失败的任务，未知回执与输入冲突仍拒绝。`--status [--json]` 只读显示运行中、待核验、失败或已核验。`epw_phonon --all` 只准备当前可运行脚本和剩余清单。

独立手工 `sbatch` 没有程序登记的回执，不生成正式科学完成记录。作业内无 DFTFlow 辅助命令，也不采纳手工改过的正式脚本身份。
