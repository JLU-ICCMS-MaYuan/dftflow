## 问题与目标

目前编号工作区的 `submit.sh` 通过 `--workspace-attempt` 调用 EPW 阶段程序，原生子任务通过 `--workspace-task` 间接执行，用户无法从实际提交脚本直接读出科学命令。

目标是：使用三个公开 EPW 入口的 `-s` 时，实际提交给 Slurm 的作业脚本直接写出相应 QE、Wannier90、EPW 可执行程序、参数、工作目录以及输入输出，便于检查和 debug。

## 范围

- 覆盖 `epw_phonon`、`epw_wannier`、`epw_superconductivity` 的 `-s`，包括其支持的阶段选择、恢复及准备路径。一次调用只提交一个当前可运行的原生任务并立即返回。
- 参考用户指定的 `epw_writesubmit.py`、`epw_submitjob.py`、`qe_writesubmit.py`、`qe_submitjob.py` 的直接命令写法；资源、路径与参数仍读取 DFTFlow 当前配置。
- 实际科学调用直接出现在被提交的脚本中；不能仅新增展示脚本，实际仍提交内部执行器包装脚本。
- 作业脚本只包含 Slurm 设置、环境加载、目录切换及一次原生程序调用；不包含 DFTFlow 输入准备、质量核验、状态记录或推进命令。环境和目录切换保留必要的失败判断。
- 用户再次运行公开命令时，由作业外程序核验上一任务、更新记录、准备下一输入并提交下一任务。活动／未知任务阻止重复提交，失败任务通过显式恢复重试；全部完成时仅报告完成，不再提交。
- Tc 搜索也逐次推进：每次只提交一个模式、一个温度、一个初值的一次求解；下一温度、第二初值、分类及最终结果核验由后续公开调用推进，保留原算法和次数上限。
- 保留相容上游复用、失败阻断、预算、身份核验和防重复提交等约束，职责移到作业外；不新增长期等待进程、后台调度器或计算节点嵌套提交。
- 提交成功输出任务、实际脚本路径、作业号和后续操作，用户能够对照脚本找到本次输入及原生日志。只读状态区分运行中、已结束待核验、失败和已核验完成。
- 允许直接修改脚本并手工 `sbatch` 独立调试；手工结果不自动登记为正式完成。正式提交不接管修改过的脚本，恢复时重验来源和产物，冲突报错，不静默导入。
- `epw_phonon --all` 保留，但改为生成当前可准备的原生脚本和待完成步骤清单；不提交任务，不再生成自动串联全流程的总提交脚本。

## 复审结论与取舍

四项选择分别回答了作业脚本辅助命令、后续衔接、手工调试及总生成入口问题。采用后来的明确选择，替代初稿允许辅助步骤及未决调度的描述。用户在完整复审修订计划后答复“开始”，授权本轮按该方案修订；没有把其他 Issue 的确认或原始“新建”要求当作本版逐字确认。

“一份脚本对应一次原生调用”来自已展示的复审方案，配合手动推进，使失败退出和实际程序清楚可见。输入准备、文件交接、原生输出解析、预算登记和科学完成判断由作业外公开命令承担，不在 shell 中复制第二套科学流程。

## 范围外事项

不扩展 EPW 公开程序数量，不重写科学算法，不改变物理参数、选窗策略、质量标准或作业资源；不把独立 Wannier90 路径与 EPW 内置 Wannier 路径强行互换。不整体重构独立 qeflow／wannierflow 提交方式，不复制参考脚本中的 Python 实现、机器硬编码或无关清理命令。不建立自动推进服务，不自动接管任意手工调试结果；`-r` 的整体重构不在本项范围。不覆盖历史冻结脚本、默认安装或旧计算数据，不提交真实科学作业，不自动推送。
