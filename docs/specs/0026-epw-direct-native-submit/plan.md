# 0026 实施计划

用户已明确要求“开始帮我修改代码！”，按已选择的纯原生命令、手动推进、独立调试及准备清单实施，不再重复请求实施许可。

## 设计与职责

- 原生任务记录拥有脚本、命令、输入与程序身份、调度回执、预算预留和原生日志。脚本只执行一次科学程序，不调用公开或私有 DFTFlow 入口。
- 公开命令持有控制锁；先查询原任务，再归集日志和退出状态，调用已有科学校验器，最后最多提交一个新任务。未知回执保留预留，禁止重复。
- 复用现有科学执行函数的准备和归集边界；原生执行边界在准备／提交后交回公开命令。再次调用时使用固定记录归集；不得重复复制运行中的保存树或归档已完成子任务。
- Tc 的暂停不算失败、不增加第二次计数；原尝试校验后继续原搜索与双初值规则。失败仍须显式恢复。
- 新脚本使用独立文件名和文件名形式日志、固定工作目录；历史封存脚本只读。手工运行不会更新正式状态。

不提交真实 QE/EPW 作业，不切换默认安装，不改数值标准；只提交本任务相对已有脏工作树的修改。

## 安装与一次性迁移

从已提交源码隔离构建，按 epwflow 模块打包私有运行库并覆盖现有三个入口，避免夹带其他未完成工作。枚举历史脚本与固定尝试记录，先检查调度队列，保存原文和哈希，再按真实输入/argv 生成单调用脚本。原记录不改写为新身份，脚本仅供独立调试；正式 `-s` 继续由原生任务记录管理。旧总提交入口退役为说明，多个科学调用各自保留独立脚本。安装后通过受控工作区验证零提交准备和直接原生执行。
