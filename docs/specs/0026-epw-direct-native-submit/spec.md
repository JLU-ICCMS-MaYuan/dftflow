## 背景与目标

当前提交脚本通过内部参数转入 Rust 执行器，再由程序决定启动何种科学程序。即使能读到阶段名，用户也难以从脚本确认实际命令、输入、输出与执行顺序。目标是让 `-s` 提交的脚本本身成为可读的执行依据，方便核查和定位失败。

### 需求结论与变更取舍

直接科学调用适用于 EPW 管理链中实际需要的 QE、Wannier90 和 EPW 程序；独立 Wannier90 与 EPW 内置 Wannier 使用各自现有科学路径。不因“直接调用”新增一套科学算法或改变已经选定的程序。

0024 的日志与失败处理要求继续适用。本项解决科学调用被内部执行器隐藏的问题，不能以脚本更短或日志路径更短替代验收。

## 用户场景与验收

### US1（P1）：提交前后都能读懂实际执行命令

用户使用三个公开 EPW 入口的 `-s`，查看实际提交的作业脚本，能够确认相应可执行程序、参数、输入、输出及运行目录。

**优先级理由**：直接回应用户无法判断如何提交、难以 debug 的问题。

**独立验收**：通过公开 CLI 捕获真实调用的 `sbatch` 参数，读取目标脚本并执行受控原生替身，核对参数、目录、输入字节和输出位置。

1. **假如**需要 QE 计算，**当**执行相应公开入口的 `-s`，**那么**实际目标脚本直接包含所需 `pw.x`、`ph.x` 或相应后处理命令。
2. **假如**需要独立 Wannier90 或 EPW 计算，**当**提交对应阶段，**那么**脚本直接包含该路径实际需要的 Wannier90／接口程序或 `epw.x`，保留必要顺序。
3. **假如**提交成功，**当**查看 CLI 输出，**那么**能获得作业号与实际目标脚本路径，不需要从内部 JSON 推导命令。

### US2（P1）：debug 时能定位失败步骤并可靠恢复

用户从原生日志识别失败步骤，通过既有公开恢复操作生成新的直接调用脚本，相容的成功上游可复用。

**优先级理由**：可读性不能以失败后继续计算、重复消耗或错误复用为代价。

**独立验收**：注入环境、目录、原生计算及结果核验失败，验证退出、后续命令未执行、成功状态未发布，以及恢复复用与预算记录。

1. **假如**关键步骤失败，**当**脚本结束，**那么**失败可从退出结果及日志定位，后续依赖步骤不执行，不发布成功交付。
2. **假如**上游已相容完成，**当**恢复失败阶段，**那么**新的实际脚本只执行必要科学步骤，保留旧失败证据。
3. **假如**作业活动、提交结果未知或输入身份冲突，**当**再次提交，**那么**继续阻止重复执行或不相容复用。

### 边界与异常场景

- 路径含空格时，可执行程序、输入、输出、环境加载与目录切换仍正确。
- SCF／NSCF 产物产生后才能决定的输入，必须在依赖可用后准备，不能为提前展示命令而伪造数据；真正启动程序的命令仍须出现在其实际提交脚本中。
- 多科学步骤与总提交路径均可对照实际脚本追踪顺序；不因直接调用而在计算节点暗中嵌套提交另一套科学作业。
- 原生程序零退出但日志或必要产物不合格时，仍视为失败；不能以 Slurm 提交成功代替科学完成。
- 旧冻结脚本、已有尝试和预算记录不原地改写；新脚本与旧恢复证据的兼容边界在设计阶段明确。
- 手工 debug 修改后不得继续冒用旧脚本身份；重新纳入受管理流程时须使用新尝试并核验来源。本项不承诺任意改写后的脚本可直接获得有效交付。

## 需求

### 功能需求

- **FR-001**：三个公开入口的 `-s` 必须提交直接执行所需科学可执行程序的脚本，覆盖受支持的阶段选择、恢复和总提交路径。
- **FR-002**：科学程序调用必须出现在实际被提交的脚本中，明确可执行程序、launcher、参数、目录、输入及输出；不得只生成另一个展示脚本。
- **FR-003**：不得再通过 `--workspace-attempt`、`--workspace-task` 或等价内部执行器隐藏科学程序启动；必要辅助入口只能承担明确的数据准备、核验或记录职责。
- **FR-004**：直接调用须沿用相应科学路径的程序和依赖顺序，覆盖实际需要的 QE、独立 Wannier90、接口／后处理及 EPW 程序；不强行互换独立与内置 Wannier 路径。
- **FR-005**：执行路径、资源和参数继续来自当前有效配置；不照搬参考脚本的机器硬编码、无关清理或调度系统扩展。
- **FR-006**：`-s` 提交成功必须报告实际脚本路径和作业号；科学日志与输入须可由该脚本定位。
- **FR-007**：关键环境准备、目录切换、科学执行或核验失败时，必须停止后续依赖执行并报告失败；原生失败保留非零退出结果，零退出的无效科学结果也不得放行。
- **FR-008**：保留运行身份与输入快照核验、预算预留和结算、活动／未知任务防重、成功上游复用及失败恢复；准备和核验不得再次成为隐藏科学执行器。
- **FR-009**：生成脚本遵循 0019 和 0024 的约束，不注入严格选项、不生成 `|| exit $?`；Slurm 日志只写文件名且保存在对应脚本目录，跨目录提交也需满足。
- **FR-010**：默认生成与 `-s` 使用同一科学命令生成规则；历史冻结脚本与数据保持原样，修改脚本后的重新登记边界须明确。

### 关键实体

- **实际提交脚本**：`sbatch` 真正接收的脚本；包含本次科学命令及必要辅助步骤，关联一次提交身份。
- **原生计算步骤**：某程序在指定目录读取指定输入并产生输出的执行单元；参数和来源应能核验。
- **提交与完成证据**：作业号、脚本身份、来源及原生结果核验记录；提交成功与科学完成分别判定。

## 成功标准

- **SC-001**：三个公开入口各有 `-s` 行为证据，受支持阶段及恢复／总提交路径全部覆盖；实际脚本中的科学命令与受控执行记录一致。
- **SC-002**：所有受测脚本可直接定位程序、参数、目录、输入和输出，不再以内部科学执行器替代调用；默认生成与提交规则一致。
- **SC-003**：正常路径和带空格路径通过 shell 语法及行为验证；关键失败、零退出无效结果均阻断依赖与成功发布。
- **SC-004**：相容复用、失败恢复、活动／未知防重、身份冲突与预算边界回归通过；冻结历史输入与脚本保持不变。
- **SC-005**：按 0024 的共同用例验证日志目录、命名和失败写法；操作文档提供从 CLI 输出找到实际脚本、原生日志及恢复入口的示例。
