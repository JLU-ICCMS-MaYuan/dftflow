# 需求规格：阶段归档后保留当前作业 Slurm 日志入口

原始需求及范围见 [Issue](issue-draft.md)，沿用用户已授权的真实运行、配置修改与自动修复。

## 用户场景

真实作业 1313468 的 Slurm 日志随阶段目录移入历史，阶段目录中看不到当前日志。Slurm 仍持有旧 inode，简单复制不能保留后续输出。

## 功能需求

- FR-001：阶段归档后，仅对当前合法 SLURM_JOB_ID 对应的普通日志文件建立同 inode 硬链接，保留历史现场及阶段目录入口；不触碰旧作业日志，不改冻结脚本，不放宽脚本哈希保护。文件系统不支持时明确失败。
- FR-002：当前配置、上游身份及冻结脚本保护继续生效，不修改物理参数或质量门。
- FR-003：用公开程序验证失败、恢复和错误拒绝，不以协议测试替代科学验收。

## 验收标准

SC-001：公开运行时保持打开的日志句柄，在归档前后写入，验证阶段目录文件 inode 与句柄一致且内容完整；真实恢复作业验证日志留在阶段目录；无严格 shell 选项。

SC-002：保留原始证据，完成规范构建／安装检查，文档反映真实边界，只提交本需求修改。
