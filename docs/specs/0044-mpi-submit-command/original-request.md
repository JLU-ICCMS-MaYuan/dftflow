> ## 目标与依据
>
> `exec` 用于以启动器替换 shell 进程，当前脚本没有必须依赖它的技术要求。改为普通 `mpirun` 调用，并通过作业加载环境后的 PATH 查找启动器。

> ## 实现与接口
>
> - 检查 QE、EPW、VASP、Wannier 及组合工作流的科学命令生成路径；去掉科学调用前的 `exec`，保留原参数、重定向和执行顺序。
> - 裸命令或带目录的 `mpirun`，在生成的提交命令中统一输出为 `mpirun`。EPW 加载配置时不再依赖登录节点 PATH 将其固化为绝对路径，也不要求登录节点预先存在该命令。
> - 在共享执行组件中复用最小命令前缀处理，分别适配参数数组和命令字符串；只修改启动器位置，保留其余文本、引号和变量语义。
> - 保留现有环境加载与失败判断。单调用脚本以科学命令结束，使退出码自然成为脚本退出码；多步骤脚本继续显式阻止失败后的后续执行。
> - 不新增 CLI、TOML 字段或开关。科学程序路径、自定义启动器、`mpiexec`／`srun`、用户 Slurm header 继续遵循现有配置；构建脚本等无关位置的 `exec` 保留。
> - PATH 查找失败直接报告执行失败，不回退到旧绝对路径；来源记录继续校验科学程序和环境脚本，不再把登录节点解析的 MPI 文件当成实际启动器身份。
