## 背景与目标

用户希望脚本直接、易读，并使用已经激活的 MPI 环境。统一生成规则并落实到实际安装和现用脚本，避免只改源码而使用行为未变。

## 用户场景与验收

### US1（P1）：生成可读且可运行的科学脚本

独立验收：通过各模块生成器创建脚本并以隔离启动器执行。

1. 登录 PATH 无 mpirun，环境脚本将其加入 PATH 后，生成脚本运行成功，参数与重定向保持。
2. MPI 缺失、环境加载失败或科学程序非零退出时，脚本失败且依赖步骤不执行。

### US2（P1）：实际安装和现用脚本生效

独立验收：核对安装哈希并运行安装版生成／执行回归；对比迁移前后的冻结数据指纹。

1. 更新实际安装后，同一公开命令生成普通 mpirun 调用。
2. 已绑定脚本原文保持，未冻结现用脚本更新；历史回执继续指向原文件。

## 功能需求

- FR-001：所有自有科学脚本的调用不加 exec，mpirun 通过作业环境 PATH 查找，旧目录写法生成时规范化。
- FR-002：EPW 不在登录节点定位或要求存在 mpirun；保留科学程序及环境脚本校验。
- FR-003：并行参数、输入输出、引号、变量、环境和失败处理保持有效，不添加严格 shell 选项。
- FR-004：无新 CLI／配置开关，科学程序路径、自定义启动器、mpiexec／srun 及用户 header 保持原语义。
- FR-005：更新仓库分组安装及固定 current；构建来自本任务提交，不纳入无关工作树修改。
- FR-006：现用脚本分类迁移，冻结脚本／配置、回执、科学数据和预算不改写，不提交真实作业。

## 成功标准

- SC-001：各受影响生成器实际脚本满足普通调用，环境加载后可找到 mpirun。
- SC-002：环境失败、缺失启动器及非零科学退出均被拒绝，参数与复杂路径回归通过。
- SC-003：相关模块和工作区回归通过；既有失败或环境限制单独记录，不冒充通过。
- SC-004：安装版行为核验通过，迁移前后受保护文件指纹一致。

## 边界、依赖与假设

继承 0019／0026 的环境、日志、手动推进、防重及科学核验边界。PATH 运行时解析 mpirun，因此不再承诺冻结登录节点的启动器文件身份。用户 header 原样保留；其他启动器不改变。无高影响待确认问题，无新增持久模型和公共接口，故不建立 data-model.md 或空 contracts/。
