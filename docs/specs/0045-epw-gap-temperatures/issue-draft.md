# 0045：通过 TOML 指定温度点计算 iso／aniso 超导能隙

唯一类型：`type:feature`。本地草案标识 0045，不代表线上 Issue 已创建或同号；origin 为 Gitee，当前无 Gitee CLI，沿用线上用户管理约定。

## 原始需求记录

> 那你为什么不把这个逻辑写到代码里面？你可以新建一个 issue 和 spec，让用户可以 在 toml 文件里面通过指定温度点来在指定的温度点下面计算超导能隙。无论是各向异性还是各向同性。这个功能不就是 epw 里面提到的指定超导温度的温度点的方法吗？只不过我强制你在 20，30，40k 进行。

此前执行范围原话：

> 我不需要你确保算出来的超导温度是不是正确。我也不需要你做事有界诊断。我只需要你给我跑通几个温度点的 iso 和 aniso 的超导温度即可。只要能正常的跑完一个 epw.x看到最后正常跑完就行。你可以选的温度点是 20，30，40 K这些非常典型的温度点。不需要考虑是不是要拿到最合理的 Tc

## 问题与目标

此前六个温度点是另行运行 epw.x；公开第 8 步仍强制搜索 Tc。用户应能直接在统一 TOML 中列出温度，用现有公开命令执行所选模式的能隙计算，完成列表后结束。

## 范围与验收

- 新增指定温度模式，支持 iso、aniso、both；温度列表可配置，20／30／40 K 不写死。
- 直接求解非线性能隙，不搜索 Tc，不额外运行双初值或自动增加温度；单点使用一个配置初值。
- 保存每点输入、日志、退出码、正常结束、收敛状态和可用的 Δ／Z；正常执行与能隙数据有效性分别报告，不将未收敛输出冒充有效能隙。
- 沿用公开命令、逐任务 Slurm 提交、预算、来源保护和显式续算；成功点复用，活动／未知作业不重提。
- 保留现有 Tc 模式和旧配置；真实 MgB₂ 通过公开入口完成六点，更新实际安装和可复制 README 命令。
