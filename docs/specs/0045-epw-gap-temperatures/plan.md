# 0045 实施设计草案

以 [Spec](spec.md) 为待确认基线，不先写入产品实现。按配置→原生尝试→调度与恢复→交付→公开入口→安装实测的顺序实施。

## 配置与兼容

新增 `superconductivity.task="gap"|"tc"`，缺省 tc，序列化旧缺省时不引入无意义指纹变化。gap 复用 `gap_temperatures_k`，单初值新增 `initial_gap_mev`（gap 缺省 10 meV）。gap 不要求旧 `initial_gaps_mev` 双初值或 iso/aniso Tc 表；tc 保持原验证。详见 [接口](contracts/config-cli.md)。

混合延用原 `mixing_beta`，目标 EPW 负值表示线性混合，正值为 Broyden；允许 `0<abs(beta)<=1`，历史长度保留原 1～8 约束。当前例拟显式使用 -0.3，实际 iso／aniso 均由公开入口验证，不将历史只验证过 aniso 线性混合写成新 iso 已验证。

## 原生执行与调度

复用 `attempt.rs` 的输入渲染、来源验证和原生提交。每点设置 nstemp=1、temps(1)=目标温度、tc_linear=false，分别选择 liso／laniso；不调用 Search、线性分类或双初值分类。提取通用的进程结束证据和可选能隙解析，旧 Tc 严格收敛收集继续保持，不全局放宽旧验证器。

新增独立温度点调度组件，复用已有尝试、预算、Slurm 与锁；通过现有 scheduler 按 task 分派。一次 `-s` 最多提交一个原生调用，完成后重复公开命令核验并推进。执行正常但未收敛的点保存结果并继续下一点；原生退出失败等沿用失败停止与显式恢复。

## 完成与交付

指定温度交付使用明确任务标识和独立的点结果结构，不给旧 ModeResult 伪造搜索阈值或已定位状态。阶段完成门分派核验点计划与证据；执行完整与数据有效分别记录。旧 schema 1／2 Tc 清单读取和验证保持，新指定温度清单采用可区分的新版本。

F5 根据任务归集逐点状态和有效能隙；完整虚轴数据沿用原结构，频率／温度图可使用已收敛且有效的单初值数据，不要求 Tc 分类，不插补缺失点。不绘制虚构 Tc 图或把正常态零能隙丢弃。无有效能隙时报告原因并保留执行记录。

## 来源、复用与验证

任务和单初值纳入第 8 步身份。当前第 7 步指纹依赖温度列表首项，不能为了复用旧数据删除该事实；根据生成输入和现有契约确认影响，需要重算时沿用原预算，不能只修改哈希。旧 Tc 和新 gap 状态隔离，旧现场保留。

先通过配置／真实格式原生证据测试和完整公开进程续算回归，再构建和安装仓库 bin/epwflow 三个程序；不扩展到无关模块。安装版生成与隔离执行验证后，在原预算内执行当前 PBE 六点。README 保留代码块形式，逐条说明产物。清理沿用用户此前条件，仅在从干净输入到六点的全流程可运行性得到验证后处理，不能由单元测试代替。
