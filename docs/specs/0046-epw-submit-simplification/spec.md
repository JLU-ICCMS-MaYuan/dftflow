## 背景与目标

用户需要在命令中断后再次执行同一公开命令推进流程，不被残留工作区锁拦住。此次集中修复工作区控制／执行锁，并保留五项明确的脚本可读性与输出要求，以便逐项实现和验证。

### 需求结论与变更取舍

采用最新指令：仅移除工作区及阶段的控制／执行锁；预算账本、campaign 注册表及其锁暂不调整。此前“删除全部锁，包括预算账本锁”的答复仅保留为历史，不能继续作为当前实施依据。

其他状态合并、历史清理和迁移／归档／出图等锁的批量移除均退出本次范围。锁修复优先、可独立交付；五项脚本优化单独验收，不用其他状态整理阻挡这一修复。

## 用户场景与验收

### US1：中断后直接重复命令（优先级：P1）

用户在同一目录执行公开命令，中断后再次执行，不需要手动清理 `control.lock` 或 `execution.lock`。

**优先级理由**：这是已复现、直接阻碍用户操作的缺陷。

**独立验收**：只交付工作区锁修复即可验证；不依赖脚本命名或其他状态精简。通过公开 CLI 在隔离目录保留旧空锁、带 owner 锁，并实际中断一次命令后重试。

1. **假如**存在旧工作区控制／执行锁，**当**再次执行相同公开命令，**那么**不因这些锁拒绝，不要求先手动删锁，也不创建替代锁。
2. **假如**公开命令中断，**当**重新运行该命令，**那么**进入已有作业／阶段状态处理；不新增锁恢复流程。
3. **假如**已有登记的 Slurm 作业仍活动，**当**顺序重复命令，**那么**显示已有作业状态，不重复提交，也不因“锁存在”报错。提交结果未知或计算失败仍按原有作业／科学状态处理。

### US2：读懂并运行提交脚本（优先级：P2）

用户能从脚本用途、环境和命令直接看出计算输入、输出和工作目录；同一用途可反复生成覆盖。

**优先级理由**：保留用户另外明确提出的五项优化，但不扩大锁修复范围。

**独立验收**：用受影响生产入口生成代表性 QE SCF／NSCF／PH、后处理及 EPW 粗细网格／超导脚本，运行隔离脚本核对输入输出与退出结果，不提交真实科学计算。

1. **假如**再次生成同一用途，**当**查看目录，**那么**仍为同一 `<用途>.sh` 和 `slurm-<用途>.log`，没有随机命名的正式脚本或重复阅读副本。
2. **假如**计算开始输出，**当**进程尚未结束，**那么**已能在指定 `.out` 读到科学输出，后续解析同一文件，不从 Slurm 日志复制。
3. **假如**生成脚本，**当**阅读正文，**那么**目录只在正文切换，oneAPI 直接 source，普通参数不逐个单引号，必要引用仍保护特殊路径。

### 边界与异常场景

- 同目录不同用途不撞名；不同目录同一用途可同名，文件名不添加哈希、时间或作业号。
- 路径含空格、引号或 shell 元字符时保持参数原意；不为可读性无条件拼接参数。
- 工具在脚本目录调用 sbatch；手工提交时先进入该目录，正文 cd 不负责改变 Slurm 打开相对日志的位置。
- oneAPI 按新要求直接 source，不包 if、失败后缀或严格选项；计算程序非零退出仍是失败。
- 工作区控制／执行锁移除后，不承诺多条命令同时写同一工作区时的互斥；预算读写及其锁保持原样，不扩展到预算并发设计。
- 科学输入／输出与作业记录仍按现有机制核验；不能把命名中的哈希取消扩展为取消全部数据校验。

## 需求

### 功能需求

- **FR-001**：新生成脚本采用固定 `<用途>.sh`，同目录用途可区分，不产生带随机标识的正式脚本或重复阅读副本。
- **FR-002**：Slurm `--output`、`--error` 均为 `slurm-<用途>.log`，允许反复覆盖，不含目录、哈希、时间或作业号。
- **FR-003**：支持标准输入的 QE／EPW 程序直接以 `< 输入.in > 输出.out` 运行，输出采集与科学解析读取该实际 `.out`，不从 Slurm 日志拼装；MPI 数目和科学程序不变，种子参数程序保留自身接口。
- **FR-004**：仅保留正文工作目录切换，生成器和提交参数不再加 `--chdir`；公开提交入口仍在脚本目录提交。
- **FR-005**：已配置的 oneAPI 环境用直接 `source <脚本> --force`，不包 if、失败后缀、额外子 shell 或自动严格选项。
- **FR-006**：普通命令与参数直接显示，仅对需要保护的值进行必要引用，不逐个单引号，参数含义不变。
- **FR-007**：移除 `epw-state/control.lock`、`epw-state/execution.lock` 和阶段目录中同类 `execution.lock` 的创建、获取、释放、恢复及入口拦截；旧残留不影响再次执行公开命令，不用其他锁或自动锁恢复框架替代。不据此批量移除其他种类锁。
- **FR-008**：仅对固定脚本／Slurm 日志覆盖所必需的提交回执和输出读取作适配，合法覆盖不触发旧身份冲突；保留现有活动作业识别、失败判断，不借机重构整套状态记录。
- **FR-009**：预算账本、campaign 注册表、对应锁及读写逻辑保持原样；其他状态文件、科学交接、归档、迁移、提交链、比较／交付／绘图机制暂不调整。
- **FR-010**：保留三个公共 EPW 程序、科学配置、温度点、资源与累计预算；锁修复可独立实现验收，不增加配置开关、替代工作流或无本需求来源的任务。

### 关键实体

工作区及阶段执行入口、一个用途对应的提交脚本、科学输入／输出、已有作业记录。继续使用现有实体；不新增状态仓库，不改变预算账本所有权。

## 成功标准

- **SC-001**：旧空锁、带 owner 锁及实际中断公开命令后三类场景，通过 CLI 顺序重试均不再因工作区控制／执行锁拒绝，不需手动删锁，无替代锁。该项独立验收。覆盖 US1、FR-007。
- **SC-002**：已有活动作业、提交结果未知、计算非零退出仍按既有状态正确处理，顺序重复调用不重复提交同一活动任务。覆盖 FR-007、008。
- **SC-003**：US2 各类受影响脚本满足固定名称、同名 Slurm 日志、正文 cd、直接 source 与必要引用；重复生成无随机脚本或重复副本。覆盖 FR-001、002、004～006。
- **SC-004**：隔离执行时计算未退出即可读取指定 `.out`，退出后解析同一文件；合法覆盖脚本／Slurm 日志后仍可推进，不依赖复制 Slurm 输出。覆盖 FR-003、008。
- **SC-005**：代码差异不包含预算账本／注册表锁移除和其他状态清理；相关行为检查确认其锁与读写功能仍在。科学配置、公共入口和预算累计值不因本修复改变。覆盖 FR-009、010。
- **SC-006**：受影响公开命令与脚本行为回归、脚本语法检查通过；验证锁修复时不中断真实计算，不用源码字符串匹配代替公开 CLI 的中断／重试验证。覆盖两个故事。
