# 设计研究：声子自动链

## 决策与依据

1. 单 Slurm 分配顺序执行。工作区已有 Attempt／freeze／execute 能完成快照、预算和分配核对；扩展声子路径，避免新增调度器。一次命令不要求单作业，但该方案最小且符合现有同步科学调用。
2. 在现有 native_jobs 增加已分配执行模式，保留旧 generation 和任务键。已验证原生调用直接复用，失败后只执行未完成项；不会为每个原生调用再次预留预算。
3. 所有必要科学校验仍在原调用返回后进行；下个调用开始前将前一回执登记为已验证，防止只因退出零就跳过科学有效性。
4. worker 使用同一个 native_workspace 阶段遍历及 0047 绘图；完整成功与失败结果写入父 Attempt，用户无需再次调用 -s 触发最终登记。
5. 只在 phonon 目标使用自动链。历史逐任务的合法回执在启动时 reconcile 后沿用；活动或未知旧作业阻断，新配置依照科学身份重建。其他目标不改。
6. q2r、两类 matdyn 和原始 PH 使用现有输入／格式解析，不新增科学算法或参数。
7. 复制固定快照后的结构／路径文件以内容参与绘图请求键，保留原始身份核验；避免只因副本路径不同就重复补图或把完整阶段显示成未完成。旧图回执的键不匹配时仅重绘一次，不重跑科学计算。
8. 调度器超时或取消可能来不及写 worker 失败状态。只读查询结合已知父作业终态展示失败；显式恢复在父分配终态确认后，将未完成原生调用按失败处理。有合法 PH 检查点则保留，无检查点的 PH 现场先归档再重试。

## 排除方案

- 反复在登录节点循环执行 -s：依赖常驻进程，不能保证退出终端后继续。
- 计算节点循环 sbatch：增加资源、账本、部分提交与未知回执边界。
- 只跑 ph.x 后让 coarse 收尾：不满足用户新要求。
- 整阶段失败清空目录重算：破坏 PH 等成功结果复用。

## 验证边界

公开进程与真实 shell 配合受控科学／Slurm 替身验证工作流，不作为新的科学精度验收。已有真实数据可用于只读图像查看；本轮不授权覆盖真实算例或切换默认安装。
