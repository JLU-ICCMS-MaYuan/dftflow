# 技术决策与证据

- 决策：每方法一次原生多温度调用。理由：用户认可讲义方式及两个独立作业；当前 readin.f90 支持完整 temps 与 nstemp，相等点数走列表模式，最多 50 点。拒绝逐温度 shell 循环。
- 决策：作业按方法独立登记。理由：现有 native-active.json 只代表单任务；复用既有 Task、预算、脚本与终态读取，增加 iso／aniso 两个有界指针，避免第二套调度器。
- 决策：批次保留逐点证据。理由：既有交付消费单点 Request／GapStatus；将完整日志按真实 itemp／温度分段，复用严格 Δ／Z 校验；拒绝把整份多温度日志冒充单点。
- 决策：失败后显式恢复剩余点。理由：用户已选择保留现场，原生遇不收敛可能停止；已完成点仍可验证，输入日志快照在覆盖前保留，不自动变更收敛参数。
- 决策：默认 0.13 只作用于省略字段及新示例；显式旧 0.05 保留。理由：已确认显式配置优先，不能把默认值改动当作修改所有历史科学输入的授权。

原生多温度机制说明：supercond_iso.f90 在收敛后更新 gap0，后续温度使用原生初值续接。initial_gap_mev 是批次配置的起始能隙，不表示逐温度重启并强制恢复同一初值；显式恢复的新批次重新使用配置初值。此处说明原生机制，不新增求解算法。
