# 数据模型与完整性约束

本文件是待审阅设计，尚未定义生产中的新文件格式。需求见 [Spec](spec.md)，执行边界见 [契约](contracts/cli.md)。

## 来源与复用判定

复用判定必须具备以下事实，不能只检查文件存在：

| 信息 | 内容与约束 |
|---|---|
| 科学身份 | 请求／结构／配置指纹、原阶段来源、已有科学完成证据 |
| 模型身份 | 第 5 步实际拟合模型指纹；第 6 步粗网格来源指纹 |
| 声子模式 | 当前选择的 nosplit／index／coords；只读对应目录 |
| 文件身份 | 相对来源位置、字节大小、内容哈希与已有清单绑定 |
| 位置 | 晶体／笛卡尔坐标表示、倒格基、真实 k／q 坐标、路径分段或网格偏移 |
| 统计口径 | 网格权重、单位、共同费米能、展宽、自旋计数、ASR 和原子质量 |
| 计算状态 | 已核验结果与派生结果分开，未知或失败证据不当作成功来源 |

结果包内保留足以复查比较的来源元数据和哈希；原工作区绝对路径只作解释，不是重绘依赖。原生大文件不强制复制入 results；数值表与图参必须自包含。

## 必要计算说明

在比较派生目录保存可复查的决策记录，粒度按一次必要原生调用；实施时复用现有任务／发布记录承载，不另建全局状态管理器。

| 字段 | 语义 |
|---|---|
| decision | 直接复用、转换整理、必要求值或拒绝 |
| inputs | 已核验的输入及其身份 |
| checked_outputs | 已检查目标数据及其点位／规则 |
| reason | 具体缺项或不相容事实；必要求值必须在执行前写入 |
| programs | 最少程序及用途；禁止以“后处理”笼统隐藏重做拟合或 PW／PH |
| expected_outputs | 要补的样本、网格、规则与位置 |
| actual_outputs | 执行后记录实际输出及其哈希 |
| attempt | 关联现有作业与尝试回执，恢复时避免重复成功调用 |

直接复用、拷贝和单位转换不能伪报为新科学计算。来源损坏或未知身份应拒绝；缺目标采样但模型完整时才可能进入必要求值。

## 比较表及绘图参数

尽量复用现有电子／声子比较表格式，添加必需元数据，避免维护两份数值真相。

- 路径表：实际点序号、分段身份、真实 k／q 坐标、物理路径距离、两侧能量／频率、配对范围。不能仅存归一化横轴。
- 电子 DOS 表：共同能量轴、双方 DOS、网格与权重身份、展宽、费米能、自旋计数；注明从已有 NSCF 能量重累计的来源。
- 声子 DOS 表：共同频率轴、双方 TDOS、网格与权重、展宽、质量和声学修正规则。第 6 步不含元素投影。
- 窗口信息：实际 `dis_win_min/max` 与 `dis_froz_min/max`，绝对值及相对共同费米能的值、单位和真实 wout 来源。未使用的边界如实标识，不虚构数值。
- 差值信息：保留 0043 的事实最大差值、单位、点位与有效配对范围；未配对态单列，不给自动评级。
- 图参：图型、曲线方法、QE 实线／插值虚线、颜色、标签、单位、窗口、展宽与格式信息，足以从包内表格重绘。
- 第 4 步元素 DOS：复用真实逐原子贡献及结构映射，随单侧图发布；不混入第 6 步对比表。

## 根 results 与阶段包

拟定根索引 `results/index.json` 采用版本化格式，其最小含义如下；具体序列化应在实施时兼容已有交付协议：

| 字段 | 约束 |
|---|---|
| schema_version | 新阶段索引版本，从 1 开始；不能冒充已有结果包版本 |
| workspace_identity | 标识同一计算工作区／请求来源 |
| entries | 已完整发布的阶段结果单元数组 |
| entries[].stage | 编号阶段与真实所选声子模式 |
| entries[].unit | 子任务／图组标识；第 3 步能带与 DOS 分开 |
| entries[].manifest | 包内相对清单路径，拒绝越出 results 的路径 |
| entries[].manifest_hash | 关联完整、已核验阶段清单的内容哈希 |

根索引是派生导航，可由完整阶段包重建；不能拿它代替 epw-state 的工作流状态，也不能靠手改索引“登记”科学完成。

阶段包使用现有 delivery 能力组织以下信息：包版本、阶段／单元身份、来源指纹、数值表、绘图参数、图片及各格式哈希、实际程序路线、比较口径、窗口、差值和未配对说明。第 5 步包独立于第 4／6 步；第 6 步总览绑定第 5 步电子数据指纹，并把重绘需要的电子数值和图参纳入完整结果目录。

## 状态与发布一致性

逻辑状态是现有状态系统内的职责划分，不要求新增以下同名磁盘文件：

1. **科学证据有效**：原生结果及身份已核验，可作为检查点；不是最终图表全部交付。
2. **派生数据就绪**：比较表、图参、窗口与来源已核验。
3. **单元已发布**：图像、数据、清单完整，已通过发布校验。
4. **阶段交付完成**：该阶段所有应交付单元均已发布，随后才记录最终交付成功。

每个完整单元先发布清单，再更新根导航；恢复优先重验已有清单与发布 journal。部分发布不能把整个阶段标成完整，但完整子任务应保持可见。采用已有发布锁与恢复机制避免并发写索引丢条目；活动／未知作业仍服从现有防重规则。

## 版本和旧布局

已知旧路径 `6.epw-coarse/comparison-native/electron`、`5.epw-wannier/native-post` 及 `6.epw-coarse/results` 只作为有界只读来源。核验后导出派生结果，不搬移原科学产物、不改旧清单内容或冻结脚本。新包显式标明读取的旧版本及来源，旧版本无法提供必要身份时报告缺项，不能重捕哈希冒充已核验历史。
