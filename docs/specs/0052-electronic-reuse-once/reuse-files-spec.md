## 背景与目标

当前 stages::closure 展开祖先并额外加入电子参考；native_workspace 先预检再遍历推进；reusable 再递归核验上游。编号布局的 manifest 加载还会扫描原生数据并重建内存清单，因此仅删除 JSON 文件或改输出不足以消除多余读取。

目标是以本次计算真正需要的文件为接续边界，让用户从 reuse 输出直接看出数据来源，避免历史阶段、清单重建和其他阶段派生交付阻断当前任务。

## 已确认结论与旧约束替代

- 本修订替代原 0052 中“每次新调用重新检查电子及其上游”的强制行为；历史 spec.md、plan.md、tasks.md 和验收保留为旧实现证据。
- 替代 0064 中与本需求冲突的递归批次／来源追查，但保留作业身份、活动及未知回执防重复、原生日志和收敛判断、必要配置与 XML 语义检查。
- 清单取消覆盖本次 EPW 接续链的持久及内存清单、文件指纹和产物登记，不扩展到其他模块；禁止以新名字、新缓存或新严格模式恢复相同机制。
- 保留原生科学数据、原生重启文件、阶段日志、作业号和现有配置记录；取消登记不等于删除科学数据或取消原生日志成功判断。
- 不设计全流程自动补算上游。第 1～8 步逐项数据讨论暂停；第 2 步及快照去留未确认，不将先前建议当作结论。

## 用户故事与验收场景

### US1：只接续当前任务的数据（P1）

直接所需文件可用时开展本步，不访问无关历史阶段；缺文件时指出具体路径并停止，不重算上游。

### US2：看懂 reuse 的数据来源（P1）

按实际来源阶段归组列出文件；未取用的阶段不出现。纯状态检查与“本阶段已完成”不冒充文件接续。

### US3：已有模型直接插值（P1）

不重做 Wannier 化的粗、细网格任务不因拟合窗口日志或上游电子态缺失而被包装层阻断。显式费米能设置仍可使用；fsthick 等真实计算参数保留。

## 功能需求

- FR-001：按当前任务实际读取、复制或链接的前序计算文件确定接续范围，不按全部祖先展开核验。
- FR-002：直接所需文件缺失时报告具体路径并停止，不自动补算来源阶段；电荷密度和原始波函数按 0067 免预检，实际 I/O 错误正常传播。
- FR-003：reuse 首行为 `reuse: <编号阶段名>`，随后每个真实文件独立一行，恰好前置 7 个 ASCII 空格；按实际来源归组、不重复，不使用示例伪路径或省略号。
- FR-004：不递归核验历史阶段，不读取无关电子参考、PDOS 或声子材料，不顺带刷新其他阶段图表；当前目标自己的必要后处理保留。
- FR-005：取消 EPW 接续链对 manifest、文件集合／尺寸／哈希指纹及产物登记的生成、重建、读取和强制验证；不能只取消落盘而继续全量内存重建。实际计算格式／维度检查不属于登记机制。
- FR-006：既有 Wannier 模型的后续插值不再读取 .wout 复查 dis_win/dis_froz 或 guiding_centres；Wannier 化自身的窗口设置与收敛检查保留。fsthick 与拟合窗口分开。
- FR-007：不强制从上游取得费米能或完整 NSCF 本征能量；按原生 EPW 设置运行，允许显式指定费米能，默认不强制覆盖。不得以窗口验证为由重新加载上游电子态。
- FR-008：保留结构、赝势、当前输入及 XML 的必要语义检查，保留程序执行错误、科学日志、收敛检查和调度防重复；不得用指纹恢复已取消的来源追查。

## 成功标准

- SC-001（US1，FR-001/002/004）：直接输入齐全而无关旧阶段不可访问时，公开调用仍能准备／执行当前目标；无关科学程序及后处理调用数为零。
- SC-002（US2，FR-003）：捕获实际复制／链接与输出，两者文件来源一致；续行恰为 7 空格，未取用阶段输出数为零。
- SC-003（US1，FR-005）：旧清单缺失或过期均不阻断，不读取、生成或重建清单／指纹；受控损坏直接输入仍按格式或原生错误拒绝。
- SC-004（US3，FR-006/007）：既有模型插值不需要 .wout 窗口证据或上游 NSCF 本征值；默认费米能及显式设置两条路径均验证，沿路径等特殊用途不被强制改写。
- SC-005（US1，FR-008）：活动／未知作业不重复提交；原生计算失败及未收敛不登记成功；电荷密度与波函数免核验边界不变。
