## 原始需求记录

> 再新建一个 issue，我想让所有的标准错误输出和标准正确输出都到输出文件里面。比如 ：
> xxx.x < xxx.in > xxx.out 2>&1
> 这样来写。而不是 2 > xxx.err
>
> epwflow里面所有的文件的 slurm 脚本都这么改写。

补充确认：

- 日志范围：“仅合并科学程序”。
- 已有脚本范围：“生成器及可修改脚本（推荐）”。

后续实施授权原话：

> 开始落地这个需求。

## 目标与范围

epwflow 全部阶段的 Slurm 科学程序命令统一使用：

```bash
mpirun -np N xxx.x < xxx.in > xxx.out 2>&1
```

- 覆盖声子、Wannier、粗细网格 EPC、iso／aniso 超导及相关后处理命令。
- 使用种子名等参数接口的程序保留原调用参数，仅统一输出重定向。
- 覆盖脚本生成器，以及未冻结、未被提交记录绑定的现用脚本；迁移前核对绑定状态。
- 同步调整完成检查、日志身份记录、归档与恢复逻辑，新任务不再依赖独立的科学程序 `.err` 文件。
- Slurm 自身的日志指令保留现有设置；历史脚本、输出及回执保持可核验。

## 验收标准

- [x] 全部相关生成入口使用 `> xxx.out 2>&1`，不再生成科学程序的 `2> xxx.err`。
- [x] 隔离执行中，程序写入 stdout 和 stderr 的内容均进入对应 `.out`。
- [x] 程序非零退出仍被识别为失败，不因合并日志改变退出码或完成判定。
- [x] 新任务没有科学程序 `.err` 时，完成检查、归档和恢复正常；旧任务仍按原记录校验。
- [x] 可修改现用脚本完成迁移；冻结脚本、历史输出和回执未被改写。
- [x] 生成脚本通过 `bash -n`；覆盖带空格路径及各阶段的针对性回归。
- [x] Slurm 调度日志设置保持原行为，无需提交真实科学作业完成验收。
