# 0053：研究与取舍

## 问题分类

这是新的日志维护需求。脚本生成、异步作业归集、分配内子调用及方法收尾均在 `native_jobs`；只替换重定向会导致三条归集路径因缺少 `.err` 失败。单温度超导还会强制登记 `.err`。Slurm 日志属于调度层，不在本次合并范围。

## 决策

1. 使用任务版本 3 区分合并日志，旧 1／2 保留严格校验。拒绝仅凭文件存在自动判断，以免掩盖缺失旧 `.err`。
2. 复用现有 stdout／stderr 身份及报告字段；版本 3 两字段别名同一 `.out`，只捕获一份。复制和科学产物登记去重，不生成空 `.err`；不引入新的日志模式配置。
3. 合并使用 Shell 的 `2>&1`，保留直接调用和最后命令退出码；不使用管道或等待结束后拼接日志。
4. 可修改脚本仅在未提交且未被冻结记录绑定时迁移；历史、活动和未知任务不改。共享 qeflow 和普通本地执行器不扩展范围。

## 现场依据

MgB₂ 现用 `1.qe-scf/scf.sh` 被版本 2 的 `native-active.json` 和原生任务记录绑定，作业号 1343700；历史 `epw-state/history/` 同样保留。不可直接替换脚本或重捕获哈希冒充旧任务，需由后续正常新任务生成版本 3。

所有脚本清点、迁移结果与测试结论见 [验收](acceptance.md)；初始证据不是验收通过。

## 后续 SCF 重跑语义

用户明确选择“修改 --resume：即使 SCF 已成功，每次执行也强制重新计算”。因此本次改变 `--stage scf --resume -s` 的公开语义，不通过删除现场或手工改写绑定记录实现一次性重置。

判定限制为登录端、提交模式、恢复参数和 SCF 目标同时满足；在既有调度归集及并行方法检查之后，跳过阶段复用与原进度批次，复用 `archive_step` 保留整个旧目录，再生成新批次。普通 `-s` 负责完成归集并保持幂等，其他目标的 SCF 依赖及分配内接续保持复用。运行中、调度未知、旧日志缺失及来源身份冲突仍由原边界拒绝。

不增加新的 CLI 开关或日志模式，不将强制重跑扩展到全部阶段。历史任务的记录不重写成版本 3；只对新任务使用当前生成器。
