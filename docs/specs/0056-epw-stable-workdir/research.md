# 0056 设计依据

## 现状证据

现有 archive_step 整体 rename 阶段目录；preserve_active_logs 以硬链接恢复日志。原生作业同时写现用键记录与 history 副本，当前恢复从现用记录读取。native-attempts/history 保存失败重试证据。工作区布局可单独读取，无须科学程序与完整配置。

## 取舍

公共 archive_step 将阶段目录的直接子项逐个移动到历史的 calculation/，不重命名阶段根。先保存现用阶段脚本；所有移动成功后恢复脚本并继续原来的状态失效过程。当前 Slurm 的日志通过硬链接备份到归档，原位置不移动；其余条目移动前检查目标不存在。错误通过上下文给出源／目标，向上传播阻止计算。归档中断保留已移动内容；下次显式恢复保留现存历史并归档剩余内容，不自动合并或覆盖历史。

不选择整体复制大目录或建立新的后台服务。保留现有科学缓存和恢复职责；只处理已确认的目录稳定性与显式清理。

## 数据与兼容

历史 calculation/ 内的相对布局不变，旧历史不迁移；阶段根 inode 稳定。
