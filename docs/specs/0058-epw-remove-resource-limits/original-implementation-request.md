# 删除 EPW 存储与计算时长限制

## Issue 与 Spec

沿用仓库约定，建立本地 Issue 草案及 `docs/specs/0058-epw-remove-resource-limits/`，唯一类型为 `type:feature`；线上 Gitee 由用户管理。

标题：**删除 EPW 的存储空间和计算时长限制**。

保存完整需求原文和本次“直接拒绝旧字段”的选择，配齐 Spec、Plan、Research、Tasks、接口契约及验收记录。

## 需求与实现

- **FR-001**：删除 `resources.wall_seconds`、`resources.storage_bytes`，同步清理配置模板、示例和配置序列化。
- **FR-002**：按已确认选择，配置出现旧字段直接报错，指出文件和字段；不忽略、不自动改写历史快照。
- **FR-003**：所有 EPW 新生成脚本及提交命令不添加 `#SBATCH --time`、`sbatch --time` 或替代性时长限制。
- **FR-004**：删除单次时长、累计节点时和存储额度校验；预留、分配登记、恢复、状态刷新及结果收集均不得通过旧限额阻断任务。
- **FR-005**：移除 CLI 的 `--wall-seconds`、`--storage-bytes`。保留历史账本记录，但历史时间与存储上限不再参与新任务准入，状态不再显示其为有效额度。
- **FR-006**：不新增“无限额”配置或开关。其他资源参数、作业身份和重复提交检查保持原行为。

旧快照含被删除字段时明确拒绝，不承诺无缝续算；说明应从清理后的源配置生成新尝试，禁止指导用户直接修改带哈希的冻结快照。

## 验收

- **SC-001**：删除两项字段后的配置通过公开 CLI 校验；任一旧字段仍存在时明确报错。
- **SC-002**：覆盖声子、Wannier、粗细网格、超导及其子任务，生成脚本和实际提交参数均无程序添加的时长限制。
- **SC-003**：历史账本即使已超过原时间或存储额度，新任务仍可进入正常提交路径。
- **SC-004**：活动或未知作业仍禁止重复提交；失败、恢复及历史证据保护回归通过。
- **SC-005**：使用隔离调度替身验证，不为本次删除限制启动真实科学计算。

## 文档与交付

实现验证后更新 EPW Overview、使用手册和相关示例，明确：**DFTFlow 不再额外限制计算时长和存储空间，集群自身规则仍由 Slurm 管理。**

当前仍处于规划模式，尚未创建文件或修改代码。进入实施后，验证通过即按仓库格式自动提交，仅包含本任务变更；不推送、不操作线上 Issue。
