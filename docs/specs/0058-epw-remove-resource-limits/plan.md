# 实施计划

## 基线与职责

配置层负责拒绝旧字段并带文件上下文；脚本／提交层负责移除时间注入；账本只保留登记、历史计量和已有并发约束，不做时间／存储准入；科学层不增加替代超时。

## 实施顺序

1. US1：调整 Resources、配置加载与两个 CLI 定义，清理所有测试配置和当前示例。
2. US2：账本旧额度以可选历史值保留，新账本不写时间／存储上限；新预留只登记身份，不要求预计时间／存储。旧分配只验证登记身份，保留一致性及并发防护。
3. 删除所有 EPW 脚本生成器和 sbatch 调用的时长设置，删除无人使用的存储限额模块。
4. 增加公开 CLI、超额账本、脚本／提交参数回归；同步已有用例与冻结状态测试。
5. 通过 EPW 全回归及受影响共享 QE 检查后，回写 Overview／使用说明与验收，审核任务专属暂存内容并自动提交。

## 兼容与边界

账本保持 schema_version=1，旧可选额度原值保留，新账本省略。新登记的时间／存储计量为零，实际节点时仍依据 sacct 结算；旧登记数值保留。不将旧额度列在 status 的有效 limits 下。

配置仍拒绝未知字段，不增加自动剥离或全局宽松解析。已有冻结快照、回执哈希与历史脚本不回写。文档按 [接口契约](contracts/resources.md) 说明旧配置处理。
