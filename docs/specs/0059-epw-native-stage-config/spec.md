## 背景与目标

科学参数命名与原生程序一致，使用户能从配置直接找到阶段、输入段和实际采用值。

## 用户场景与验收

- **US1（P1）**：打开配置即可定位各编号目录及子任务的原生参数；独立验收对应 SC-001。
- **US2（P1）**：独立修改阶段参数，正确判定依赖与冲突；独立验收对应 SC-002。
- **US3（P1）**：使用新版配置清除旧计算并从头获得实际交付；独立验收对应 SC-003～005。

## 功能需求

- **FR-001**：采用 schema_version=2，单文件按编号目录、子任务、程序及原生输入段组织。
- **FR-002**：科学参数使用对应程序原生名称、单位和含义，单位只写在注释及契约中。
- **FR-003**：原生数组按原生变量名表达，卡片保留原生名称及内容；结构派生卡片列明来源。
- **FR-004**：覆盖八阶段及现有所有后处理，当前硬编码科学设置均整理到所属阶段。
- **FR-005**：同名参数各阶段分别填写，无跨阶段继承；缺失必填项指出完整路径。
- **FR-006**：工作流设置独立分组；自动推导有明确来源，手填与推导双重定义拒绝。
- **FR-007**：上下游必须匹配的数据身份、网格和模型维数冲突时列出双方，不静默改值。
- **FR-008**：输入、回执和复用身份使用本阶段有效配置；第七步温度独立设置。
- **FR-009**：三个计算 CLI 保持现有接口，仅接受新版配置，不提供旧配置兼容或迁移。
- **FR-010**：验证后清除当前算例旧计算内容、旧状态、results、native-plan.json 和旧 RESULTS.md，不备份归档；保留目录、新配置、README 和 KPATH，不跟随外链。
- **FR-011**：从 SCF 重跑八阶段，保持 PBE、小网格、iso/aniso 及 20/30/40 K 能隙目标；保留共享账本累计消费，失败不自动扫描参数。

## 成功标准

- **SC-001**：每个实际科学输入参数有配置或推导来源，名称和单位与目标程序一致。
- **SC-002**：阶段独立、依赖失效、冲突拒绝和旧配置拒绝测试通过。
- **SC-003**：公开 CLI 的输入生成、提交、恢复、比较和双方法求解回归通过。
- **SC-004**：清理符合 FR-010，外部结构、赝势和账本不被删除或重置。
- **SC-005**：真实八阶段完成，双方法全部目标温度通过现有收敛与数据检查。
- **SC-006**：文档、参数契约和实现一致，任务差异验证后按仓库格式提交。

## 假设与依赖

沿用 Rust/Bash、当前 QE 7.4.1 配套 EPW 5.9 与内嵌 Wannier90。程序命名和单位以配套原生源码/文档核对。原共享账本保留消费记录；另项 0058 已取消的时间/存储限制不恢复。

## 边界与异常场景

旧版、混合结构、未知参数、非有限值、非法数组、路径逃逸和模式冲突在执行前拒绝。依赖于尚未计算结果的值在该阶段执行时核验，不能用猜测值替代。
