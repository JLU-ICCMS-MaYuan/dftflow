## 背景与目标

避免在 TOML 保存冗长点表，确保电子态按用户指定完整网格计算，并在数据交接前发现 QE 添加点或实空间 FFT 不兼容。

### 需求结论与变更取舍

采用用户最后澄清：核对 NSCF 实际输入和输出数量，不比较 SCF 与 NSCF 对称约化后的实际点数。SCF 与 NSCF 的设置网格仍须相同。

简写数组属于配置层便捷表达，实际 QE 输入仍使用原生 `K_POINTS crystal`；此项明确替代 0059 的 NSCF 完整点表配置。SCF 保留原卡片形式，不偷偷复制上游值到下游配置。

## 用户场景与验收

### US1：简短配置生成官方同义网格（P1）

用户填写三个正整数，由程序生成完整科学输入。独立验收：SC-001、SC-002。

1. 假如 SCF 为 2×3×6、零位移，NSCF 配置为 [2, 3, 6]，当生成输入，那么实际文件包含 36 点，数值、顺序和精度与官方脚本一致。
2. 假如维度冲突或含非法值，那么计算前指出配置路径并拒绝。

### US2：在错误电子态进入 EPW 前停止（P1）

用户希望实际输出严格对应提交的点表。独立验收：SC-003、SC-004。

1. 假如输入 36 点、输出 40 点，那么非零退出，报告双方数量和文件，建议改用 pw.x 的 bands 模式，后续科学程序不启动。
2. 假如输出恰好 36 点但存在重复或不对应坐标，那么同样拒绝。
3. 假如 SCF 约化为 16 点，而 NSCF 输入和输出均为 36 点，那么数量检查通过。
4. 假如用户明确改为 bands 模式，那么仍生成完整均匀点表，执行相同输出检查，不自动重试。

### US3：保护已有声子响应的 FFT 接续（P1）

用户能在进入 EPW 前发现电子保存树与 PH 响应不相容。独立验收：SC-005。

1. 假如 SCF 与 NSCF 密度 FFT 分别为 216×128×60 和 216×125×60，那么拒绝登记有效接续，报告双方尺寸与 XML 来源。
2. 假如后续输入已有 PH 响应与电子网格不相容，那么进入粗网格前拒绝，不重算或插值修改 PH。

## 功能需求

- **FR-001**：第 2 阶段网格接受恰好三个正整数的 K_POINTS 数组，采用零位移；不要求在 TOML 列坐标。
- **FR-002**：核对 SCF 与 NSCF 三个网格维度一致，SCF 非零位移明确拒绝；不比较两者约化后的实际点数。
- **FR-003**：实际输入由 Rust 生成，方法、点序、坐标与权重的打印数值与官方 kmesh.pl 一致；生产不依赖 Perl。
- **FR-004**：完成后从本次已绑定 nscf.in 和输出 XML 读取实际数量；核对声明点数、坐标行数和电子态记录数，不只比较配置推算值。
- **FR-005**：校验输出点集完整、无重复、与输入逐点对应、权重符合归一化后的等权重，容差须覆盖官方打印舍入但不能吞掉相邻网格点。
- **FR-006**：数量或点表不一致时非零退出，不发布阶段成功、不调用下游；列出双方文件、数量及恢复建议。
- **FR-007**：第 2 阶段允许 calculation=nscf 或 bands；建议使用 pw.x 的 bands 模式，不自动改值、不调用 bands.x 替代、不自动重试。
- **FR-008**：支持 nr1/nr2/nr3 与 nr1s/nr2s/nr3s 原生参数；每组三维完整、为正整数，错误说明所属阶段；未指定则保留 QE 默认选择，不静默填值。
- **FR-009**：解析并对照实际 SCF／NSCF 密度和光滑 FFT；对接 PH 时检查其来源及尺寸，匹配前不得启动粗网格。不从响应文件字节数单独推断唯一三维网格。
- **FR-010**：配置、生成输入和实际输出身份进入既有回执与复用校验；旧有效结果也须满足新交接检查，缺失或冲突时报告，不自动重算 PH。
- **FR-011**：文档注明 k 点与 FFT 为不同网格；SCF 重新计算，声子不重算；源码、安装、受控测试和真实科学结果分别报告。

### 关键实体

- 网格设置：三个正整数及 SCF 位移，决定完整点数。
- 本次实际输入：带身份的完整点表及模式，是输出检查的依据。
- 实际电子态：QE XML 的点数、坐标、权重和带数。
- FFT 身份：实际保存树的密度／光滑三维网格与可核查的 PH 来源。

## 成功标准

- **SC-001**：简写配置生成 A×B×C 行点表，SCF／NSCF 网格冲突和非法值在提交前拒绝。
- **SC-002**：1×1×1、2×3×6、6×6×6、4×4×2、2×3×7 的 Rust 输出与官方脚本数值及格式对照通过。
- **SC-003**：输入 36、输出 36 通过；输出 35／40、声明数与记录数不同，以及等数量错点／重复点均失败，且失败后下游调用数为零。
- **SC-004**：nscf／bands 两种模式均经真实入口受控测试；SCF 16、NSCF 36 的合法约化场景通过。
- **SC-005**：216×128×60 与 216×125×60 明确失败；密度匹配但光滑不匹配也拒绝，完全匹配通过；错误包含来源和维度。
- **SC-006**：已有数据复用与失败恢复执行同一检查；检查失败不发布成功，也不触发自动 PH 重算。
- **SC-007**：文档按 FR-011 同步，回归通过；真实 SiP₂ 验证后续由用户提交，不以受控测试冒充科学验收。

## 假设与依赖

依赖当前 0059 原生阶段配置；沿用 Rust/Bash、QE 7.4.1、配套 EPW 5.9 及现有三个计算入口。官方脚本以仓库 external/wannier90/utility/kmesh.pl 的版本和哈希冻结为验证依据。采用数组 [A, B, C] 表达用户的 A×B×C，不增加第二套字符串表达。

## 边界与异常场景

非法维数、零负数、非整数、乘积溢出、重复坐标、额外点、缺失 XML、FFT 不匹配或缺少可证明来源时停止；不靠原生进程零退出放行。精度和逐点比较细则在 Plan 固定并通过官方脚本对照。

## 范围外事项

本项不实现外部 save 导入、不复制 SiP₂ 大数据、不重算 PH、不开发 SCF 导入、不判断插值是否科学收敛、不新增超导参数或自动扫描、不自动部署或推送。
