# 0062 规格

> **协作入口（2026-11-17）**：[GitHub Issue #62](https://github.com/JLU-ICCMS-MaYuan/dftflow/issues/62)。Issue 已在 GitHub 登记，协作状态以 GitHub 为准；本文件保留设计与历史验收，旧的“本地草案／线上自管／未发布”说明是迁移前语境。Spec 远程链接待发布及验证。

## 目标

用户打开新生成的科学输入时直接看到原生标题或输入段；参数来源独立记录，不占据文件开始部分。

## 行为要求

- FR-001：PW 的 SCF、NSCF 和能带输入不前置卡片来源中文说明。
- FR-002：共用 namelist 配置器不添加逐参数来源说明；覆盖 PH、q2r、matdyn、bands、DOS、projwfc 与 EPW 调用。
- FR-003：保留原生标题、全部数值、单位、数组索引和卡片；旧来源行传入配置器时仍可移除，不删除其他注释或标题。
- FR-004：冻结提交与直接准备模式的 parameter-map.json 保留平层配置位置及内部绑定来源；*.parameters.json 保留实际输入哈希和配置归属，双重定义与未登记参数仍拒绝。
- FR-005：逐条说明用户原需求、助手自行扩展的契约、引入提交及实际执行语句，不以 Git 配置的作者身份推断责任。
- FR-006：不改写已完成或已提交计算绑定的历史输入、回执、预算和数据，不重跑科学计算或切换默认安装。

## 验收标准

- SC-001：SCF/NSCF/能带输入从 &CONTROL 开始，无参数来源头；PH、后处理及 EPW 输入无这类说明，保留合法标题。
- SC-002：去掉旧来源行后科学输入逐字节等同于直接生成；数组和卡片回归保持。
- SC-003：JSON 来源与实际输入哈希一致，冲突拒绝回归通过。
- SC-004：公开 CLI 的准备、提交、恢复和结果发布回归通过；提交/运行使用隔离替身，不属于科学验收。
- SC-005：截图中原文件哈希保持，来源记录与当前说明一致；仅提交本任务差异。
