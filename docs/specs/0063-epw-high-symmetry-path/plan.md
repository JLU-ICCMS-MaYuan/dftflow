# 实施计划：高对称端点路径

**Issue**：[GitHub Issue #63](https://github.com/JLU-ICCMS-MaYuan/dftflow/issues/63)。**Spec**：[spec.md](spec.md)。日期：2026-10-27。

## 授权与阶段门

用户已明确“开始执行。”。用户随后明确同坐标才算差值、无同坐标不算、保留 DOS、不注明共同点覆盖率，据此统一实施。线上 Gitee 及远程链接仍由用户管理，不把本地实现记作线上关闭。

## 技术上下文

Rust 2021、现有 qf-input、serde、QE／EPW 和内嵌 Wannier90；生产 Rust/Bash，隔离进程协议测试使用既有 Python fixture。目标 Linux HPC。持久数据沿用阶段文件、JSON 来源和结果包，不新增服务或依赖。

## 设计

1. `electronic_sampling.rs` 从端点源文件构建真实边，而不是从展开点反推端点。兼容现有 VASPKIT 文件头和裸端点对，校验非法坐标、标签、空路径、零边及原生行长。
2. `wdata` 每条真实边一行，保留真实标签和分数坐标；带数、能窗、NSCF 和原生参数所有权不变。
3. 读取原生 `*_band.kpt`、`*_band.dat`、`*_band.labelinfo.dat`，按实际坐标、端点和连续段验证，不能按人工横轴恢复。
4. 双方保留完整原生曲线，差值统计只取相同坐标、相同路径位置和相同连续段的原生值，不注明覆盖率。postw90 保留 DOS 求值职责；电子路径输出不再包含网格本征值，不再展示缺失的逐点电子网格差值。第 6 步用带哈希的第 5 步电子表格和统计生成总览，声子路径及网格仍按原有口径。
5. 历史人工路径只按已核验的旧来源有界读取，不改写冻结输入、成功模型或历史回执。

## 源码触点与职责

`epwflow/src/interpolation/electronic_sampling.rs` 负责端点和原生采样读取；`epw_config.rs` 负责 wdata 集成；比较统计及出图仍属于 `foundation/workspace_plot.rs` 与既有 comparison 模块；科学调用与发布仍属于 `foundation/workspace_science.rs`。不新增第二条科学执行链。

## 自定义文件头回归修复

本次属于主路径历史输入兼容遗漏，不改变端点、比较或 DOS 的职责。FR-011／SC-007 对应 T008～T010：按非空、非注释记录识别完整四行文件头，标题不限定材料或固定前缀；随后严格解析全部端点，保留物理行号。不会通过宽泛跳过非数字行实现兼容。

先用真实 SiP₂ 路径内容补失败回归，再修复解析器，运行库与公开入口恢复测试。测试不修改真实 KPATH、科学参数或回执。沿用会话已授权的正式 CLI 更新要求，从已提交基线与本任务补丁构建 release，排除无关脏改动，更新正式入口并记录哈希；不提交真实科学作业。初次实施记录的“不部署”仍描述当时边界，本次发布另列验收证据。

## 失败任务归档交接续修

FR-012／SC-008 → T011～T013：归档第 5 步已明确失败的原生任务时，按原身份核验归档输入、脚本、日志及外部来源，将原活动记录原样移入同一历史目录。保持旧任务记录、哈希及失败结论，不将失败模型作为成功数据复用。

对已出现的遗留状态，恢复入口只在显式 `--resume`、第 5 步失败任务、旧输入确实缺失、阶段进度已进入另一失败尝试时查找对应 `wannier-*/calculation`。必须唯一且完整匹配旧任务绑定的归档身份，外部来源仍须验证。无匹配、多重匹配、损坏、缺失进度及活动／未知任务均拒绝。正常路径仍走既有校验，不增加通用的“跳过旧输入验证”。

验证先复现三段失败链，再测未来归档交接、遗留状态恢复及拒绝场景。真实 SiP₂ 通过显式启用的生产 API 恢复准备测试调用 `advance(..., submit=false, resume=true)`，随后用正式 CLI 不带 `-s` 检查现场准备；不伪造调度回执、不提交科学作业。记录实际生成的输入、脚本、准备状态和旧记录归档位置，并核验前置科学身份不变。
