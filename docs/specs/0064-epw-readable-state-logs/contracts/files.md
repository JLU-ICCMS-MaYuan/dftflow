# 0064 文件契约

- `.log` 为 UTF-8 英文纯文本：标题、分隔线、工作区、当前状态、任务与进度、问题、下一步；小节使用 ASCII 方括号，键值采用 ASCII 冒号，任务使用具名小节。值中的换行转为单行可读说明，不能破坏记录边界。
- 日志只记录当前子任务，不保留旧批次执行历史。字段缺失明确为未记录，未知提交不得被读成未提交；无法解析的完整记录报出具体日志和字段。
- `<阶段目录>/<阶段名>.jobs` 为带表头的纯文本，列为子任务和 Slurm 作业号；不填写虚构任务号，不累积旧批次作业。
- 阶段日志缺失而 `.jobs` 仍有任务号时，先查询实际调度状态；运行中或查询失败均保留任务号和现场，确认终态后撤下孤立记录，再按当前输入准备。不以日志消失推断任务已退出。
- `<解析后的 work_dir>/epw-state/0000-config.toml` 起递增，至少四位；每次公开配置调用比较最大编号文件的原文字节，相同不新增，不同按最大编号加一。恢复历史内容仍是新版本，不搜索旧版本去重；不覆盖已有版本，不改写注释或排版。用户实际输入名不强制更换。
- 第 1 步日志以 `Configuration snapshot · NNNN-config.toml` 小节保存每版的绝对原始目录和原文 SHA-256；SCF 重算不得清除这些小节。读取编号配置时验证哈希，所有相对路径仍按该目录解析，普通和受控嵌套加载器行为一致。来源缺失、内容损坏、同文但来源目录不同均明确拒绝混用。
- 第 1 步日志整体丢失时，仅允许以其他阶段对唯一当前版本及原输入路径的完整绑定、显式原输入的相同字节、全部现存作业已终态为证据恢复来源记录。缺历史来源或局部损坏不自动修补；现存 `.jobs` 仍需查询后才可撤下。
- 首次运行自动核查原输入目录中的旧编号版本：按解析后的 work_dir 归属筛选，预检编号、原文、目标来源和旧任务终态；独立复制原文并登记来源后，更新八日志所有阶段及子任务的配置引用，最后移除旧位置的对应文件。目标冲突、活动／未知旧作业时保留原文件并报错；中断可重入。不得手工改哈希、修改科学输入或重算来迁移。
- 不新增 `continue.log`、JSON 工作流状态、历史归档或固定展开配置。科学程序的原生日志和结果包数据格式不受此契约改名。
- 正常重算清空本阶段可替换内容，保留阶段目录 inode 和当前打开的 Slurm 日志。退出旧布局只操作固定程序状态路径，绝不跟随链接删除外部资料。

- 新记录结束标记为 End of record；.jobs 表头为 Task 与 Slurm job ID。旧中文标记、表头、字段及已知说明仅在读取边界兼容，正常更新后写英文格式。
- 新旧名称规范化后不得出现重复小节／字段／任务；原文配置、用户路径、任务号和批次不因语言变更而改变。不新增历史备份或隐藏语言配置。
