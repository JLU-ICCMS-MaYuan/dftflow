# 0064 研究与取舍

## 实施前核对的旧行为

- `native_workspace` 在推进前 reconcile，旧输入不存在会先报错；只改报错不能解决多份状态互相制约。
- `native_jobs::persist` 同时写当前指针、按请求记录与历史记录。
- 第 3／4 步通过 `attempts` 中配置与回执启动分配；删除目录必须同步替换脚本入口。
- `workspace_science`、coarse／fine／restart／batch 仍读取共享 manifest；不能仅关闭输出。
- 声子后处理、电子和投影各有检查点，必须将成功子项的续算合入日志，避免重复科学调用。

## 决策

采用明确的中文字段与任务小节；解析与渲染共用一份字段契约。只保存当前阶段事实，不序列化整个原任务对象，不保存持久请求摘要。直接数据适配保留现有严格原生解析器，在内存重建其所需对象。用户提供的 TOML 原文编号版本是参数变化判断的依据。

不采用换后缀 JSON、嵌入 base64／JSON 块、隐藏数据库、搬到 completion.json、每任务历史目录或常驻文件监听器。`.jobs` 不复制实时调度状态；阶段日志不冒充科学输出。

多进程写日志采用短时系统锁与完整重读／原子替换，锁随进程退出释放，不遗留公共锁目录。提交回执先持久化任务号，再更新摘要，进程中断仍能从二者交叉恢复。

阶段日志被删除也必须核查尚存的 `.jobs`：已确认退出才能撤下孤立任务号，活动／未知仍保留现场。该规则同时适用于原生任务和第 3／4 步阶段分配，不额外保存第三份恢复记录。

历史兼容仅允许一次性退出固定旧状态集合；不在每个新请求中维持旧 JSON 读取分支。不自动修改示例计算现场或外部来源。
