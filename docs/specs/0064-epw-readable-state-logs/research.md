# 0064 研究与取舍

## 实施前核对的旧行为

- `native_workspace` 在推进前 reconcile，旧输入不存在会先报错；只改报错不能解决多份状态互相制约。
- `native_jobs::persist` 同时写当前指针、按请求记录与历史记录。
- 第 3／4 步通过 `attempts` 中配置与回执启动分配；删除目录必须同步替换脚本入口。
- `workspace_science`、coarse／fine／restart／batch 仍读取共享 manifest；不能仅关闭输出。
- 声子后处理、电子和投影各有检查点，必须将成功子项的续算合入日志，避免重复科学调用。

## 决策

采用明确的英文字段与任务小节；解析与渲染共用一份字段契约。只保存当前阶段事实，不序列化整个原任务对象，不保存持久请求摘要。直接数据适配保留现有严格原生解析器，在内存重建其所需对象。用户提供的 TOML 原文编号版本是参数变化判断的依据。

不采用换后缀 JSON、嵌入 base64／JSON 块、隐藏数据库、搬到 completion.json、每任务历史目录或常驻文件监听器。`.jobs` 不复制实时调度状态；阶段日志不冒充科学输出。

多进程写日志采用短时系统锁与完整重读／原子替换，锁随进程退出释放，不遗留公共锁目录。提交回执先持久化任务号，再更新摘要，进程中断仍能从二者交叉恢复。

阶段日志被删除也必须核查尚存的 `.jobs`：已确认退出才能撤下孤立任务号，活动／未知仍保留现场。该规则同时适用于原生任务和第 3／4 步阶段分配，不额外保存第三份恢复记录。

历史兼容仅允许一次性退出固定旧状态集合；不在每个新请求中维持旧 JSON 读取分支。不自动修改示例计算现场或外部来源。

## 英文输出与旧中文记录兼容

程序直接使用英文文案与字段；普通注释、规范和操作说明仍为简体中文。历史记录兼容集中在读取边界：固定词条与受控占位符用于解析旧记录，内部推导说明同时保留原有身份值，原有参数、路径和数值原样保留；新路径不做运行时翻译。兼容词条表固定描述旧格式，不成为新文案的配置入口。英文记录与旧中文记录规范化后共用同一任务、批次和科学检查逻辑。

英文记录以方括号划分小节、ASCII 冒号分隔字段，使用 End of record 作为完整结束标记。旧标记及任务号表头可只读加载，正常更新时写英文；重复的新旧别名、截断记录与任务号冲突继续拒绝。用户提供的原文、路径及原生程序输出不翻译，也不因其中含中文而丢失内容。

共享工作区同时进行的绘图修改不属于本项；测试与发布采用独立检出中的已隔离补丁，防止把未完成绘图实现混入本次制品或提交。不改变科学输入、数值规则和用户计算现场。


内部自动绑定的推导说明原本参与科学指纹，直接翻译会改变旧结果的身份。因此输出文案使用英文，内部绑定仍确定性恢复原来的身份值；原生输入和配置原文不改变。历史绑定夹具与实际配置生成测试固定该契约，防止只因语言变化而重复 SCF、PH 或 EPW。
