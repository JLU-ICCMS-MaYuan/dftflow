## 背景与目标

目前的编号工作区将运行状态分散在多份活动记录、尝试、进度、请求、共享清单和历史中。SiP₂ 现场出现失败任务仍引用已移走输入的情况，旧记录校验先于阶段重试，导致用户无法重新准备计算。

目标是让用户打开对应阶段的日志，就能读懂当前状态、计算位置、任务、已完成项、失败原因和下一步；任务号就近保存，配置版本可直接取用，续算不再依赖旧路径和额外状态目录。

### 需求结论与变更取舍

- 采用用户后续选择：续算信息统一并入八份阶段日志，不采用最初提出的 `continue.log` 备选。
- 配置变化在 CLI 调用时检查；不引入常驻监视器，不承诺保存两次 CLI 调用之间未被程序观察到的编辑版本。
- 用户本轮明确否定共享清单、失败尝试和历史保留，替代旧 Spec 的相关要求；不能把旧保护规则重新包装后强加给本项。
- 保留运行任务查询与实际科学输出检查：任务号证明提交身份，Slurm 终态证明调度结束，原生输出证明科学计算和收敛，三者不能混为一谈。
- “不保留历史”针对旧计算、工作流状态和尝试；不删除用户明确要求的配置版本及 `imports/`。
- 本轮只建立 Issue／Spec 草案与需求质量检查，不改计算现场；完整草案确认后再生成依赖它的实施方案。

## 用户场景与验收

### US1：打开八份日志即可读懂计算状态（P1）

用户只需查看相应阶段文件，无须理解 JSON、哈希键或跨多个目录拼装当前状态。

**优先级理由**：这是用户直接提出的主要体验目标。

**独立验收**：查看新工作区八份日志，对照实际状态核对每项信息。

1. 假如尚未执行任何阶段，初始化后能看到八份日志，每份明确写“未开始”，而不是空文件或伪造完成。
2. 假如声子模式为 `nosplit`，第 4 份文件为 `4.qe-phonon-nosplit.log`，内部列出布局、模式、计算目录及声子子任务现状。
3. 假如计算失败，日志能指出具体子任务、原生日志路径、失败原因、可保留结果及当前可执行的下一步；不只写“校验失败”。
4. 假如 iso 完成而 aniso 未完成，第 8 份日志分开显示两种方法和各温度状态，不用整体失败掩盖成功部分。

### US2：旧输入消失后仍能按当前配置重算（P1）

用户修改输入后重算，不需要手工修复已过期的状态文件。

**优先级理由**：直接解决当前阻断。

**独立验收**：通过公开 CLI 重现旧失败任务输入已移走的现场，再准备新任务。

1. 假如旧任务已结束且旧输入缺失，按当前配置重算时可以生成新输入，旧记录缺失不能提前终止。
2. 假如本阶段需要重算，旧的本阶段科学现场直接被新现场替换，不生成任何新的历史目录或失败尝试备份。
3. 假如仍有运行任务或提交结果未知，程序明确给出任务或未知提交的原因，不覆盖它正在使用的数据。
4. 假如只改第 5 步输入，已验证且相容的 SCF／NSCF／声子可以继续使用；受影响下游不能因旧文件还在而误判有效。

### US3：用阶段日志和任务号接着算（P1）

用户可以接续中断计算和后处理，不需要多套尝试数据库。

**优先级理由**：简化输出必须保留用户强调的续算能力。

**独立验收**：对中断的公开阶段命令重新调用，比较实际执行子任务与预期剩余项。

1. 声子已完成、matdyn 或绘图失败时，只补缺少项；可用 PH／q2r 结果直接从第 4 步目录取得。
2. 第 3 步 bands、DOS、投影分别跟踪；第 6 步比较子任务和第 7 步多个展宽分别跟踪。
3. 第 8 步 iso／aniso 及逐温度进度分别记录，保留已经完成的点，不因一种方法失败而丢失另一种方法的结果。
4. Slurm 显示 COMPLETED 而原生输出缺失、截断或不收敛时，只显示“作业已结束，计算未通过检查”，不得登记科学完成。
5. 同一命令在任务运行中重复调用不会重复提交；提交回执丢失时先登记并显示未知状态，不能假装未提交。

### US4：取得每次被 CLI 观察到的输入版本（P2）

用户可直接打开并取用编号 TOML 原文，判断自己改过哪些输入。

**优先级理由**：配置版本是用户明确要求保留的唯一通用历史。

**独立验收**：依次提供内容 A、A、B、A 调用 CLI，得到三份编号快照，分别为 A、B、A。

1. 首次读取配置时保存 `0000-config.toml`；内容变化保存 `0001-config.toml` 等后续版本。
2. 连续相同内容不重复备份；回到更早内容但不同于最近一次版本时，仍新增一个版本。
3. 备份完整保留用户原文，包括注释和相对路径；不把内部展开配置冒充用户输入。
4. 仅查看帮助、不读取配置的命令不制造配置文件。

### US5：外部声子导入继续可用（P1）

用户继续使用 `imports/` 导入外部计算的 `save/`，不因删除共享清单丢失来源。

**优先级理由**：用户明确要求保留此能力，已有导入主路径也依赖它。

**独立验收**：导入既有声子，接续后处理及下游；来源只读，未执行新 SCF／NSCF／PH。

1. 来源、转换与必要映射保留在 `imports/`，当前第 4 步日志用可读方式说明来源和导入状态。
2. 删除共享 `qe-data/` 后，下游仍能从实际数据和导入记录获取正确 q 点、响应势和电子数据。
3. 导入失败不静默转为重新计算声子，转换重试不生成 `history/`。

### 边界与异常场景

- 新工作区初始化、某阶段未执行、日志缺失／不完整、任务号表缺失、Slurm 查询失败，均需显示具体情况，不能由一个缺失文件永久阻止重算。
- 人工把日志改为“完成”不能跳过科学输出检查；缺输出时标记需要补算，不能只凭文字宣告成功。
- 输入、上游数据、网格、原子顺序或前缀变化时，重新检查相关阶段；来源判断就近进行，不能恢复 `requests/`。
- 声子模式切换后顶层仍只有一份第 4 步日志；切换前处理尚在使用旧模式数据的任务。
- 工作流重算覆盖与原生程序自身检查点续跑区分：明确重算才替换本阶段；可续接的成功子项不因统一归档被移走。
- 多方法更新同一份日志不能互相覆盖；写入中断后不出现可被误读为完成的半份状态。
- 新日志写入失败时报告具体路径；不能已提交任务却将状态回退成“未提交”。
- 旧工作区可能只有过期记录、可能有大体积历史科学数据、可能仍有活动任务；转换不得仅靠旧输入哈希可读才允许进行。

## 需求

### 功能需求

- **FR-001**：编号工作区初始化后，`epw-state/` 顶层的普通文件恰好为八份阶段 `.log`；只保留 `imports/` 这一目录例外，不引入隐藏状态仓库。
- **FR-002**：八份日志以中文标题、固定分区、明确状态和下一步提供可读文本；不得输出 JSON 对象、序列化转储或仅为程序服务的难读内容。
- **FR-003**：工作区布局和实际声子模式进入第 4 步日志，删除 `layout.json` 的生成和运行依赖；根据当前配置与真实目录定位阶段。
- **FR-004**：每次配置驱动的公开 CLI 调用检查输入原文；首次和内容变化时在输入文件旁保存递增的 `NNNN-config.toml`，连续相同内容不新增。
- **FR-005**：快照保留原文字节，编号从 0000 起且至少四位，已有编号不能覆盖；当前输入仍由用户编辑，不生成 `current-config.toml`，不强制将现有 `epwinput.toml` 改名。
- **FR-006**：删除 `parameter-map.json` 的输出及专用持久化逻辑，不将其更名后塞进其他日志或目录；科学输入仍遵循原生格式。
- **FR-007**：删除 `active.json` 和 `attempts/` 以及对应提交快照／回执目录机制；声子阶段任务信息写第 4 步日志，其他阶段任务信息写各自日志。
- **FR-008**：删除 `native-active.json` 的生成、读取和旧路径前置校验；当前阶段状态统一进入对应日志。
- **FR-009**：删除 `native-active-iso.json`／`native-active-aniso.json`，两方法及逐温度状态集中写入第 8 步日志，分别续接。
- **FR-010**：每个编号计算目录就近使用与阶段同名的 `.jobs`，仅保存当前批次的子任务与 Slurm 作业号，不另建 `native-jobs/` 或其历史；实时调度状态查询 Slurm。
- **FR-011**：阶段与子任务续算信息集中在八份日志，删除 `native-progress/`；不增加 `continue.log` 或第二套续算文件。
- **FR-012**：删除 `requests/`、持久请求指纹及其前置门槛；直接检查实际依赖阶段的数据与当前所需输入，不输出替代的请求目录。
- **FR-013**：删除 `native-attempts/`、其检查点目录和失败尝试归档；粗／细网格与比较任务的当前续算状态并入所属阶段日志。
- **FR-014**：删除共享 `epw-state/qe-data/`、`coarse/`、`interpolation/` 的持久化和运行读取依赖；相关下游就近读取实际科学数据，所需数据结构可以在内存中构造，不能换位置恢复同一套持久清单。
- **FR-015**：删除 `post/` 及共享后处理缓存，直接使用第 4 步的 PH／q2r／matdyn 产物，必要后处理状态进入所属阶段日志。
- **FR-016**：重算直接覆盖本阶段现用文件，不创建 `history/`、失败尝试目录或其他计算历史备份；配置版本和明确保留的导入数据除外。
- **FR-017**：继续保留 `imports/` 与外部 `save/` 导入功能、来源及必要映射；不得因删除共享清单而丢失真实导入来源或自动重做 PH。
- **FR-018**：从日志和 `.jobs` 恢复当前操作时，区分未开始、准备、提交中、运行中、待检查、失败、需更新、已完成和提交未知；日志同时说明作业状态、科学结果及收敛，不以文件存在或 Slurm 终态替代科学检查。
- **FR-019**：已结束任务的旧输入／输出缺失不能在重算准备前硬性阻断；按当前配置生成新现场，并更新所属日志与 `.jobs`。
- **FR-020**：保留已完成且可直接验证的子任务续算，覆盖电子子任务、PH／q2r／matdyn、比较后处理、多个展宽、iso／aniso 与温度点；不依赖已删除目录。
- **FR-021**：运行中或提交未知的任务不允许被覆盖／重复提交；错误信息具体列出阶段、任务号或缺失回执及下一步，不把旧失败记录泛化成永久禁令。
- **FR-022**：日志／任务号更新不得丢失实际已提交任务；并发方法更新、提交中断和状态半写均可被识别与接续，且不重新引入永久 JSON 事务目录。
- **FR-023**：旧工作区转换到新输出布局时保留现用科学结果与导入数据，处理已结束／活动／未知任务，退出已删状态；过程可重试，不为转换新建历史目录，不因旧输入已移动而卡住。
- **FR-024**：公开入口、状态展示、后处理、绘图、结果发布、外部导入和 `epw_clear` 均不得继续依赖被删除的状态路径；旧历史清理命令与新布局相容，不额外删除现用数据或配置版本。
- **FR-025**：唯一工作流续算依据为阶段日志、`.jobs` 和就近科学输入输出；不能把删掉的状态记录挪到 `completion.json`、结果包、`imports/` 或隐藏目录里继续维持平行状态仓库。
- **FR-026**：重算后受影响下游不得复用已失效结果；无关且相容的上游保持可用。不以已经删除的请求指纹或共享清单作为识别前提。
- **FR-027**：日志中计算路径优先相对工作区展示，原生输入、输出、Slurm 日志各有明确指向；保留既有编号计算目录及原生程序日志，不能用阶段摘要覆盖科学输出。
- **FR-028**：配置版本与记录中的参数版本明确对应；用户显式选择旧编号配置时读取的就是该版原文，而不是程序生成的有效配置。快照解析错误不冒充可用配置。

### 关键实体

- **阶段日志**：八个阶段各自当前状态、子任务、直接依赖、结果检查和续算动作的统一可读记录，不保存全部计算历史。
- **任务号表**：某阶段当前批次的子任务与 Slurm 任务号对应关系，不复制实时状态或完整任务对象。
- **配置版本**：CLI 观察到的输入原文版本；原名输入为编辑入口，编号版本为可取用快照。
- **导入来源**：外部 `save/`、转换与必要映射，保留在 `imports/`；不能承载无关状态。
- **科学现场**：实际编号计算目录内的原生输入、输出和检查点，是依赖与科学有效性检查的直接来源。
