# 实施计划

基线为 [Spec](spec.md)；用户确认沿用现有 slurm.header 并授权开始修改。

1. 配置职责：EPW 的外部 Document／运行时 Config 复用 qf-config::SlurmSection，删除 Resources；旧字段在反序列化时提供迁移提示。
2. 执行职责：launcher 是 MPI argv 的唯一来源；可识别数量仅用于原生 pool／image 约束和状态展示，不推导 Slurm 参数。不再用 SLURM_NTASKS 强制校验 MPI 相等。
3. 调度职责：复用用户 header 生成脚本；保留已有日志默认值，用户显式指令后写且优先；不生成分区／节点／任务数指令，不通过提交 argv 覆盖。
4. 记录职责：作业登记与防重复继续按实际 job id 维护，移除虚拟资源参数，消费来自实际调度证据。
5. 构建职责：沿用固定模块安装路径，成功制品覆盖；删除发布器的制品版本记录，不保留版本安装目录。

FR-001／SC-001 对应 T001；FR-002～003／SC-002～003 对应 T002；FR-004／SC-004 对应 T003；FR-005～006／SC-005 对应 T004～T005。FR-007／SC-006 对应 T006。

## 平铺程序配置补充实施方案

内部保留 `Program { path, args }` 接口，统一程序目录负责平铺字段的序列化、路径解析和独立 argv；后处理查找只使用显式配置。args 默认空列表，路径缺失且 args 非空拒绝。公开旧子表拒绝并提示迁移，不增加同目录兼容推导。所有调用（包括 qeflow 共享声子包装器、原生后处理、快照和来源清单）接入同一程序目录；移除隐式 pencil 参数。EPW image 在配置验证与阶段预检共同检查，PH 不受影响。

FR-008／SC-007 → T007；FR-009～010／SC-008 → T008；FR-011／SC-009 → T009；FR-012／SC-010 → T010。已有未提交修改以任务开始时文件副本为基线，提交时按增量构造暂存文件，不混入其他任务。
