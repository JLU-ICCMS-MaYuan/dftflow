## 原始需求记录

```text
我建议
[resources]\
partition = "local"\
nodes = 1\
mpi = 2
彻底放弃这个参数， mpi 只通过 launcher 启动。slurm 脚本的内容直接采用toml 里面读入相关的字符串，就能设置 slurm 的 ## 标志的文件头。

这个要求统一到所遇到 dftflow 里面的代码里面。

后续实施授权：

每次编写代码，都直接覆盖旧的编译的结果，或者删除旧的编译好的命令，然后重新编译，不要记录版本，直接覆盖，只保留一份编译结果。

开始修改。

后续答复：

统一采用QE／VASP 等模块已经支持 [slurm].header的方案。
```

## 需求结论

全仓库统一复用 `[slurm].header` 字符串。删除 EPW `[resources]` 外部配置和内部同名资源模型；MPI 调用仅使用配置的 launcher，Slurm 资源申请仅使用 header，不从 launcher 反推生成资源指令。Slurm 正确指令前缀为 `#SBATCH`。

## 用户场景与验收

- **US1**：用户直接提供完整 Slurm 文件头；提交脚本保留用户指令且不新增分区、节点、任务数覆盖。
- **US2**：用户仅在 launcher 指定启动参数；运行命令不被资源配置或恢复逻辑悄悄改写。
- **US3**：所有 flow 使用一致约定；Ubuntu 示例、公共模板和使用文档一致，历史计算现场保持不变。

## 功能需求

- **FR-001**：EPW 接入现有 `[slurm].header`；删除 `[resources]`，旧输入明确报错并说明迁移方式，不静默忽略。
- **FR-002**：全部新生成的 DFTFlow Slurm 脚本采用用户 header；不自动补写或覆盖 partition、nodes、ntasks 等资源申请，不通过 sbatch 参数再次覆盖。
- **FR-003**：MPI 启动 argv 以 launcher 为唯一来源；内部只在原生算法确实需要时读取可识别的进程数，不再与 resources 对照；不将 Slurm 分配任务数强制等同实际启动数。
- **FR-004**：保留作业身份、活动／未知作业防重复、真实调度状态和消费记录；节点消费使用实际 Slurm 证据，不虚构 resources 替代值。
- **FR-005**：审计 QE、VASP、Wannier、SC、替位及共享执行组件，沿用现有入口语法，不强制把其他模块的启动命令格式改为 EPW 格式。
- **FR-006**：迁移活动示例和测试夹具；更新根说明、受影响 Overview；历史验收、冻结输入和已生成脚本不批量改写。

- **FR-007**：每次成功构建直接覆盖固定命令，不创建编译版本记录、版本安装目录或入口备份。构建缓存不是另一套公开入口。

## 边界

不新增调度资源推断层，不调整科学参数，不提交新的真实科学任务，不修改系统环境脚本，不自动推送或切换分支。旧现场不保证透明续算，禁止伪造身份或改写冻结快照。构建成功后覆盖公开入口，不创建版本目录或制品版本记录；构建缓存不作为第二套用户命令。实际构建与安装结果以验收证据为准。
