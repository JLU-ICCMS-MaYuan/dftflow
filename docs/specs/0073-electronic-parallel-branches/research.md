# 设计依据

## 原有缺口

现有 run_electronic_parallel 草稿逐项同步调用 run_leaf，不能形成独立 Slurm 作业；DOS 完成判断仅检查 dos，投影仍混在绘图入口中。整阶段 DirectoryGuard 会串行化分支进程。

## 决策

- 独立分支进程复用 scoped_allocated 原生任务执行，使用分支目录锁；八日志更新已有 epw-state 锁。
- 收尾作业采用 afterany 而非 afterok：无论失败还是成功都能核验并回写；只有完整成功才画组合图。
- DOS 分支先完成总 DOS 再投影；组合图继续使用已有渲染器。
- 保留现有原生子任务检查点，避免 bands 或 projwfc 失败造成成功 PW 或 dos 重算。
- 不在同一 12 CPU 分配内同时启动两个 12 MPI 进程组。已有 -r 保持顺序。

备选方案：线程并行无法满足独立 Slurm 资源和作业恢复；仅提交原生 PW/dos 无法在同一次调用自动完成各分支后处理。

## 与 #72 的行为衔接

#73 明确将 projwfc 纳入 DOS 分支，要求两分支成功后统一绘图，因此替代 #72 历史测试中投影失败仍发布部分组合图的预期；成功的能带、总 DOS 和即时范围诊断继续保留。旧验收记录保留历史语境，本轮更新对应回归断言。
