# 实施计划：统一绘图格式配置

## 阶段与依赖

1. 验证既有 qf-config 配置层：全局 `PlotSection`、枚举、默认值、加载校验、大小写和去重。
2. qf-plot 统一输出：一次内存 SVG 绘制，转换四格式；复用内置字体和 PNG DPI；独立处理每种输出失败。
3. qf-phonon 三图及 qeflow 自动链、nosplit、单独重绘接入；同步基于格式的产物完整性检查。EPW 历史清单调用显式保留旧格式。
4. qf-scflow 从根配置传入格式，三类图保留 PDF，增加配置格式；保留旧库函数签名。
5. 更新根说明、CLAUDE.md、现有 QE 示例、受影响 Overview 及 Spec 产物。
6. 四个核心 crate、qeflow/scflow CLI、全工作区回归；实际 MgB₂ 只读数据副本重绘；编译覆盖固定入口后按文件范围提交。

依赖顺序：T001 → T002/T003 → T004–T008 → T009–T011。任务可核对来源见 [research.md](research.md) 追踪表。

## 实现原则

格式转换只在 qf-plot 维护；模块只负责绘图内容和传入全局配置。内存 SVG 消除临时文件管理，JPEG 直接编码共同 RGBA 像素，不做多余的 PNG 落盘往返。保留 scflow 的 PDF 兼容包装，不扩展未授权的其他绘图模块。

## 验证与发布

测试不仅检查路径存在，还解析实际图片、检查 PNG 尺寸和 DPI、验证 JPEG/PDF 签名、检查额外失败后的其他输出，并用完整 CLI 验证配置传播。MgB₂ 使用已有原生数值文件副本，不重算科学数据。

工作树存在 #73 等其他任务改动；只暂存本任务路径。全量验证与发布使用排除这些改动的源码快照，成功后直接覆盖原固定命令，不保留另一套公开入口。源代码测试与科学数值验收分开说明。
