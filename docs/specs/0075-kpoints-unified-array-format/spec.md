# Spec #75：K_POINTS 统一数组格式

## 用户需求原文

> 我希望把 k_shift = [1, 1, 1] 写到 K_POINTS 里面，如果 K_POINTS 长度 6 个，那么后三个就是 shift，不要增加 k_shift 新变量。

> 有一个问题是：有时候 k 点的设置不光有 k 网格，还有平移量，当前的设置兼容考虑这一点了吗。特别是在撒均匀网格点时。

## 目标与边界

把网格与偏移合并到同一数组字段，接通配置读取、校验、内部视图、配置写回及实际 QE 输入生成。保留旧 SCF 卡片读取能力，不新增用户可配置的 `k_shift` 字段。

本次不放宽 EPW 工作流已有的 SCF／NSCF 同维度、零偏移约束，不修改科学参数或提交科学计算。

## 配置契约

### EPW 的 SCF

```toml
[stages."1.qe-scf"]
K_POINTS = [8, 8, 4]
# 等价的显式零偏移：
# K_POINTS = [8, 8, 4, 0, 0, 0]
```

- 三元素数组表示三个网格维度，偏移为零。
- 六元素数组的后三项表示 QE `automatic` 卡片的三个偏移标志，取值只能是整数 `0` 或 `1`。`1` 表示对应方向的半网格偏移，不是任意整数平移量。
- 网格维度必须为正整数，并通过现有网格容量检查。
- 保留内部 `Scf.k_shift` 作为运行时视图，不把它作为独立 TOML 参数。
- 非零偏移可解析并生成正确的 QE 卡片，但当前完整 EPW 配置校验仍拒绝它，报告 `identical zero-shift grids required`。

### EPW 的 NSCF

```toml
[stages."2.qe-nscf"]
K_POINTS = [8, 8, 4]
```

NSCF 沿用 0060，只接受三正整数数组；六元素数组和显式点表均不接受。Rust 使用共享均匀网格生成器展开为完整 `K_POINTS crystal` 点表，包含零偏移坐标和归一化权重。

带偏移的网格仍然均匀。这里的零偏移限制来自当前 EPW 工作流与交付校验契约；不将其描述为“偏移破坏均匀性”。

### 独立 QE 声子工作流

```toml
[qe_phonon.scf]
kpoints = [8, 8, 4, 1, 1, 1]
```

使用既有小写 `kpoints` 字段，三元素和六元素语义与 SCF 一致。独立 QE 工作流允许非零偏移；配置加载时检查数组长度、正整数网格和 `0/1` 偏移。旧的独立 `k_shift` 字段应明确报错并提示迁移，不能静默丢弃。

既有从间距推导网格的数值写法继续工作，自动生成零偏移。

## 旧格式兼容与写回

```toml
[stages."1.qe-scf"]
K_POINTS = '''automatic
8 8 4 0 0 0'''
```

- 旧 SCF `automatic` 卡片继续读取；配置序列化时写成数组。
- 零偏移写成三元素数组；非零偏移写成六元素数组。
- 已有六元素零偏移数组可以原样往返。
- 旧 SCF `crystal` 卡片继续使用现有完整网格检查和原生卡片生成路径，不强制转换卡片类型。
- EPW→qeflow 适配把运行时网格与偏移放入同一六元素 `kpoints` 数组，避免共享输入渲染器遗漏偏移。

## 验收标准

1. 三元素 SCF 数组通过完整校验，生成零偏移 `K_POINTS automatic` 卡片，并可往返序列化。
2. 六元素 SCF 数组保留三个偏移；独立 QE 输入生成正确卡片；完整 EPW 校验保留已有零偏移限制。
3. NSCF 三元素数组继续展开完整均匀点表；六元素非零偏移被拒绝，错误说明要求三个正整数与零偏移。
4. 旧 SCF `automatic` 卡片仍可读取并写回数组，旧 `crystal` 卡片保留兼容路径。
5. 非法长度、非整数、零或负网格及非 `0/1` 偏移被配置入口拒绝；独立 `k_shift` 提示迁移。
6. 相关配置与输入回归通过；重新构建并覆盖固定模块 CLI，检查入口启动与构建制品一致性。
